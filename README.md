# Analysis_project_roht_phase2

ロート製薬フェーズ2の本解析を、再現可能かつ安全に進めるためのプロジェクトです。

## 作業開始時の必須確認

このリポジトリで作業する者は、**解析・編集・外部サービス参照・Git操作の前に、毎回このREADMEを最初から最後まで確認してください。**

続いて、[運用ルール](docs/運用ルール.md)を確認してください。解析を行う場合は、[解析上の注意事項](docs/解析上の注意事項.md)も必ず確認します。個別の解析仕様書が追加された場合は、このREADMEからリンクします。

作業前に必ず次を確認します。

1. Gitのルートが `/Users/aoiseki/GitHub/Analysis_project_roht_phase2` であること
2. `origin` が `https://github.com/aoiseki0415/Analysis_project_roht_phase2.git` であること
3. 操作対象が、このREADMEで許可されたフォルダまたは外部サービス内に限定されていること
4. 解析を行う場合は、GitHubの `docs/解析上の注意事項.md` と、Notionの `解析ストーリー` 配下にある全ページをその都度読み、最新のID対応、解析使用可否、分割記録の扱い、注意事項を確認すること
5. 生データと個人情報をGit・README・Notion・回答へ保存しないこと。匿名IDは、解析に不可欠な例外処理に限って `docs/解析上の注意事項.md` と許可されたNotion内へ記録できるが、氏名その他の個人情報と結び付けないこと
6. 解析結果の出力先が、指定されたOneDriveフォルダであること

上記を満たせない場合は作業を進めず、現在の状態を利用者へ報告します。

### 参考資料の位置づけ

参考資料には、大きく次の2種類があります。

- ガボール課題の実装資料：課題内容、実装方法、実験の進行、取得される行動データとイベント情報を理解するために使用します。
- 実験初期段階のMATLAB解析：脳波の前処理、行動データ解析、ERP・時間周波数解析など、本解析の細かな処理手順と解析手法を検討する際の重要な参考資料です。

本解析ではこれらを積極的に参照します。ただし、過去コードを無検証でそのまま採用せず、現在のデータ構造・解析方針・品質基準との整合性を確認します。

## 基本ワークフロー

1. このREADME、[運用ルール](docs/運用ルール.md)、[解析上の注意事項](docs/解析上の注意事項.md)を読む。
2. 解析を伴う場合は、Notionの `解析ストーリー` 配下の全ページを最新状態で読み、除外・スキップ・統合・条件対応を確認する。
3. 作業対象、入力データ、出力先、Gitリモートを確認する。
4. Google Driveや参考資料から、実験条件と既存手法を確認する。
5. [フォルダ・ファイル管理](docs/フォルダ・ファイル管理.md)に従い、`解析プログラム/`の該当フェーズでスクリプトを作成・更新する。
6. 生データ原本は読み取り専用で扱う。加工済み・中間データは指定された `解析に必要なデータたち/`、figure・表・集計・ログは指定OneDriveフォルダへ出力する。
   - Phase 1で保守的基準に該当する不良チャンネル候補を検出した場合は、判定figureと根拠を保存し、利用者承認なしでICA学習・ICA適用対象からだけ自動除外して処理を継続する。
   - Phase 1の脳活動解析用EEGは元の32チャンネル順・32列を固定し、ICAから除外したチャンネルもフィルタ・トレンド除去済み信号のまま保持する。32要素のICA除外mask、除外名、理由を脳活動・瞬き解析用データの両方へ付帯させる。
   - 確認用figureには軸名、単位、色・線種の意味、凡例を明記し、単位がない量は `[a.u.]` と表示する。
7. 結果を検証し、実行範囲、検証結果、警告、失敗理由、出力先を指定OneDriveの `Sub/logs/` と補助CSVへ記録する。日次作業ログや被験者別結果表は、個別の明示依頼がない限りNotionへ作成しない。
   - Phase 1では、保存完了後・前処理完了確定前に、`QC01_BlinkCheck`（Fp1・Fp2のみ）のICA前後HTMLを最大3分で全時間帯を高速走査し、瞬き成分除去精度を0～100点で概算評価する。確認後はHTMLタブを必ず閉じる。
   - 除去ICごとのtopomap PNGも確認し、Fp1・Fp2の空間的バランスを「良好／一部偏り／片側偏重」で記録する。この評価はQCであり、ICLabelの除去判定には追加しない。
   - 「ICA処理結果（ID別）」にICAの個別結果、瞬き成分除去精度、空間的バランスを記録し、「前処理完了確認（ID別）」で各IDの最終出力と完了状態を確認する。
8. リポジトリの変更を検証し、対象ファイルだけをcommitして個人リポジトリへpushする。
9. pushと、今回変更した外部文書がある場合はその読み戻し確認が完了してから、利用者へ結果を共有する。

本番一括処理へ進む前に、パイロットIDでスクリプト、パラメータ、完了条件を確定します。確定後は同じ版を全IDへ適用し、IDごとに処理を変えません。正常完了したIDを理由なく再処理せず、再処理は実装不具合、出力欠損、または合意済み仕様変更がある場合に限ります。

Notionの `解析ストーリー` は、対象IDの採否と例外処理に関するライブの正本です。過去の会話、キャッシュ、以前の集計だけで解析対象を決めません。

新しい恒常ルール、解析方針、作業結果が確定した場合は、個別の指示を待たず、その作業の一部として対応するGitHub文書とNotionページを更新します。

## Phase 1本番実行の最重要事項

Phase 1の試行実行・本番実行では、次を必ず守ります。詳細なチェックリストは[Phase 1実行README](解析プログラム/Phase1_脳波前処理/README.md)を正本とします。

1. 実行の直前に、このREADME、運用ルール、解析上の注意事項、Phase 1仕様書、Notionの解析ストーリー配下を読み直す。
2. 全IDを、GitHubで確定した同一のPythonスクリプトの実行だけで処理する。CodexがIDごとに探索的な計算、手作業の代替処理、都合のよいコード変更を行わない。
3. Python実行、出力確認、Notion記録、HTML・topomap確認、Computer Useを含む通常の前処理工程では利用者承認を求めず、ID単位の工程を最後まで完了する。許可範囲外、安全上の問題、または自力で解決できない真の阻害要因がある場合だけ停止して報告する。

6. 各IDで、確定パラメータ、入力・出力先、命名、除外mask、分割IDの扱い、QC方法が仕様どおりか確認する。

## Phase 2行動データ解析の完了状態

No1 Grand-averageのMA30には、既存の0〜1800 ms版を保持したまま、両製品群で共通の400〜1400 ms・200 ms刻み・薄いグレーの横グリッドを用いる拡大表示版も追加します。MA50、個人figure、セット別定量化は変更しません。

Phase 2のNo1（RT解析）とNo2（ミスタッチ解析）は、解析対象40被験者ペアへ同一の確定Pythonスクリプトを適用します。No1は200 ms未満のRTだけを除外し、個人RT推移、30試行幅・50試行幅の製品群別Grand-average（平均±SEM）、`AllTrials`・`Last80Trials`のセット別RT定量化を作成します。定量化の検定は両側対応ありt検定で固定し、現行の主PNGは未補正p値を表示します。CSVには未補正・Bonferroni・Holm・Benjamini–Hochberg FDRのp値を併記し、補正法の最終選択に備えます。No2とPhase 3にも同じ統計表示規則を適用します。定量化フォルダ直下には通常解析のセット別PNG・全Set統合PNG・統計CSVを置き、追加解析は内容が分かる下位フォルダへ同じ構成で保存します。再実行は、合意済みの仕様変更または成果物不具合がある場合に限ります。

## Phase 3瞬き解析の確定方針

Phase 3解析1は、Phase 1でICLabelのEye成分として除去したICのチャンネル別寄与（ICA前EEG−除去後EEGと同値）をセンサー空間へ戻し、使用可能なFp1・Fp2を時点ごとに平均した `Eye Blink Component Signal` を主解析信号として瞬きイベントを検出し、Blink Rate時間変化とセット別定量化を行います。通常はFp1・Fp2の算術平均ですが、ICA学習から一方のFpチャンネルが除外された場合は残るFpチャンネルの信号が主解析列になります。ID124・209はFp2補助列が全SetでNaNのため主解析列の実体はFp1のみですが、主解析列は有限であり、他IDと同じ処理を適用します。Peak height基準は設けず、セッション全体の候補prominence分布から `中央値 + 12 × 1.4826 × MAD` で閾値を定め、minimum peak distance 100 ms・peak width 20–320 msを固定適用します。係数12は文献推奨値ではなく、探索比較と係数10による初回全対象結果の過剰検出確認を踏まえて固定した値です。IDごとの上位一定割合を選び、抽出総数を似通わせうるパーセンタイル方式は使用しません。Blink Rateは60秒窓で算出後、セット内15秒中心化平均をかけてから進捗軸へ変換します。Fp1・Fp2単独は検出数の補助QCに限定します。主要結果は全対象を用いたまま保持し、Vロートプレミアム群には、ID233 ControlのSet 1〜3で瞬き成分が十分に抽出されていないという事後確認に基づき、被験者内対応を保つためID133–233の両条件のSet 1〜3を群集計だけから外したGrand-average・セット別定量化を追加出力します。OneDriveは `No1_BlinkRate/` 直下で製品群を先に分け、各製品群内を `Individual/`、`GrandAverage/`、`SetQuantification/`、`QualityCheck/` に分けます。瞬き抽出確認HTML・PNGは `QualityCheck/BlinkDetection/`、prominence分布PNGは `QualityCheck/ProminenceDistribution/` に保存し、被験者ペア順の命名で並べます。正式一括実行前には全40ペア・80セッション、製品群各20名、重複、対象外ID、欠測Set、HDF5構造、主解析列の有限性を出力なしで事前検証します。Notionは親ページを確定事項の要約、子ページを詳細仕様、結果を1行1被験者ペアの統合表として管理し、共通SetにおけるEye Drop／Control総検出数の大きい方÷小さい方が2倍以上なら「要確認」と記録します。現行実装の確定仕様と結果記録項目は[Phase 3 瞬き解析仕様](docs/Phase3_瞬き解析仕様.md)を正本とします。

Phase 3 No1のGrand-averageは、従来の0始まり自動スケール版を保持したまま、Cキューブ主要版、Vロートプレミアム主要版、VロートプレミアムのID133–233 Set 1〜3除外版について、3図共通の10〜30 blinks/min・5 blinks/min刻み・薄いグレーの横グリッドを用いる拡大表示版も追加します。個人図、瞬き検出QC、prominence分布、セット別定量化はこの追加出力では変更しません。

Phase 3のセット別定量化も、製品群・解析版ごとに6つの両側対応ありt検定を行い、主PNGは未補正p値を表示します。統計CSVには未補正・Bonferroni・Holm・Benjamini–Hochberg FDRを併記します。全Set統合Blink Rateは、両条件で利用可能なSetの総瞬き数を総実時間（分）で割って被験者値を作り、1回の対応ありt検定を行います。

## Phase 4脳波解析の確定方針

Phase 4は、No1 Fmθ（Fz、4–7 Hz）、独立した追加解析No1_add Fz Time-Frequency Map（Fz、1–30 Hz）、No2後頭alpha（Oz、8–15 Hz）、No3前頭delta（Fz、帯域未確定）で構成します。No1は、Phase 1のセット別脳活動解析用HDF5から全32chのWelch PSDを1秒Hann窓・1秒移動・1 Hz分解能で一度だけ計算し、4–7 Hz平均後の未平滑PSD時間変化をローカルの指定HDF5へ保存します。figure作成、Grand-average、定量化、統計、topographyは保存済みPSDを再利用し、figure調整だけでPSDを再計算しません。

No1の代表figureはFzを用い、個人時間変化、製品群別Grand-average（平均±SEM）、Set別・全Set統合定量化、全32chの `Eye Drop − Control` 差topographyを作ります。Phase 1のICA学習除外区間と1%以上重なる1秒PSD窓を全32chでNaNにした後、セッションID・chごとに利用可能な全Setの未平滑4–7 Hz平均PSDをまとめ、`log10(PSD)`の平均＋3標準偏差を超える上側値だけを、そのch・その時刻でNaNにします。閾値はSet別・条件横断では作らず、下側除外もしません。元PSD、閾値、mask、除外数・率をcacheへ残します。ICA学習用ch除外maskはPSDへ適用せず、32chを保持します。時間変化figureは両mask適用後に各Set内で60秒中心化単純移動平均をかけ、Grand-averageは平滑化後にprogress 100点へ対応付けます。定量化とtopographyは両mask適用後の未平滑PSDを使用します。既知の欠測Setは個人時間変化では欠測側だけ非表示とし、Grand-average・定量化・topographyでは対応条件側も同じSetから除外します。計算関数と全引数、Set端padding、progress変換、PSDキャッシュ構造、実行モード、各figureの寸法・軸・目盛・文字・線・色・上限、統計位置、topography設定、命名、検証条件は[Phase 4 脳波解析仕様](docs/Phase4_脳波解析仕様.md)を唯一の実装正本とします。

個人時間変化は、3SD mask適用後・60秒平滑化後の主figureを `Individual/` 直下、未平滑の閾値除外前後を `Individual/Unsmoothed/BeforeThresholdExclusion/` と `AfterThresholdExclusion/` に保存します。固定y軸版と平滑化比較フォルダは保存しません。定量化figureはPhase 3と同じ文字階層を使い、`Eye Drop`を22 pt、括弧付き製品名を18 ptで分離表示します。Topographyは両mask適用後の各Set・各chの有限な未平滑PSD窓を時間平均してから `Eye Drop − Control` を計算します。同一図の全6 Set・全32chの最大絶対差を `M` とし、`M / 0.85` 以上の切りのよい値 `V` を用いて `−V〜+V` の左右対称カラースケールにします。

Grand-averageのy軸は標準で最大 `mean + SEM` を約75%の高さに置きます。全対象の今回成果は、一部の大きな値によって通常域が図下部へ圧縮されたため、今回の再描画に限り「平均線の最大値」を約95%に置く明示的な表示オーバーライドを使用します。この基準は今後の一般規則にしません。

No1の既存スクリプトと旧仕様での全対象出力は完了していますが、今回確定したlog10 PSD上側3SD除外はまだ未実装・未再実行です。次のコード更新時に同一スクリプトへ実装し、cacheと全成果物を再検証します。No1_addも仕様確定済み・未実装であり、No1本体と別スクリプト、別cache、別OneDrive成果物として実装します。
