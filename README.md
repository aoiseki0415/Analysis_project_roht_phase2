# Analysis_project_roht_phase2

ロート製薬フェーズ2の本解析を、再現可能かつ安全に進めるためのプロジェクトです。

## 作業開始時の必須確認

このリポジトリで作業する者は、**解析・編集・外部サービス参照・Git操作の前に、毎回このREADMEを最初から最後まで確認してください。**

続いて、[運用ルール](docs/運用ルール.md)を確認してください。解析を行う場合は、[解析上の注意事項](docs/解析上の注意事項.md)も必ず確認します。個別の解析仕様書が追加された場合は、このREADMEからリンクします。

作業前に必ず次を確認します。

1. Gitのルートが `/Users/aoiseki/GitHub/Analysis_project_roht_phase2` であること
2. `origin` が `https://github.com/aoiseki0415/Analysis_project_roht_phase2.git` であること
3. 操作対象が、このREADMEで許可されたフォルダまたは外部サービス内に限定されていること
4. 解析を行う場合は、GitHubの `docs/解析上の注意事項.md` と、Notionの `解析ストーリー` 配下にある全ページをその都度読み、最新のID対応、解析使用可否、分割記録の扱い、注意事項を確認すること
5. 生データと個人情報をGit・README・Notion・回答へ保存しないこと。匿名IDは、解析に不可欠な例外処理に限って `docs/解析上の注意事項.md` と許可されたNotion内へ記録できるが、氏名その他の個人情報と結び付けないこと
6. 解析結果の出力先が、指定されたOneDriveフォルダであること

上記を満たせない場合は作業を進めず、現在の状態を利用者へ報告します。

### 参考資料の位置づけ

参考資料には、大きく次の2種類があります。

- ガボール課題の実装資料：課題内容、実装方法、実験の進行、取得される行動データとイベント情報を理解するために使用します。
- 実験初期段階のMATLAB解析：脳波の前処理、行動データ解析、ERP・時間周波数解析など、本解析の細かな処理手順と解析手法を検討する際の重要な参考資料です。

本解析ではこれらを積極的に参照します。ただし、過去コードを無検証でそのまま採用せず、現在のデータ構造・解析方針・品質基準との整合性を確認します。

## 基本ワークフロー

1. このREADME、[運用ルール](docs/運用ルール.md)、[解析上の注意事項](docs/解析上の注意事項.md)を読む。
2. 解析を伴う場合は、Notionの `解析ストーリー` 配下の全ページを最新状態で読み、除外・スキップ・統合・条件対応を確認する。
3. 作業対象、入力データ、出力先、Gitリモートを確認する。
4. Google Driveや参考資料から、実験条件と既存手法を確認する。
5. [フォルダ・ファイル管理](docs/フォルダ・ファイル管理.md)に従い、`解析プログラム/`の該当フェーズでスクリプトを作成・更新する。
6. 生データ原本は読み取り専用で扱う。加工済み・中間データは指定された `解析に必要なデータたち/`、figure・表・集計・ログは指定OneDriveフォルダへ出力する。
   - Phase 1で保守的基準に該当する不良チャンネル候補を検出した場合は、判定figureと根拠を保存し、利用者承認なしでICA学習・ICA適用対象からだけ自動除外して処理を継続する。
   - Phase 1の脳活動解析用EEGは元の32チャンネル順・32列を固定し、ICAから除外したチャンネルもフィルタ・トレンド除去済み信号のまま保持する。32要素のICA除外mask、除外名、理由を脳活動・瞬き解析用データの両方へ付帯させる。
   - 確認用figureには軸名、単位、色・線種の意味、凡例を明記し、単位がない量は `[a.u.]` と表示する。
7. 結果を検証し、Notionの「解析の記録」へ実施内容・結果・解釈・出力先を記録する。
   - Phase 1では、保存完了後・前処理完了確定前に、`QC01_BlinkCheck`（Fp1・Fp2のみ）のICA前後HTMLを最大3分で全時間帯を高速走査し、瞬き成分除去精度を0～100点で概算評価する。確認後はHTMLタブを必ず閉じる。
   - 除去ICごとのtopomap PNGも確認し、Fp1・Fp2の空間的バランスを「良好／一部偏り／片側偏重」で記録する。この評価はQCであり、ICLabelの除去判定には追加しない。
   - 「ICA処理結果（ID別）」にICAの個別結果、瞬き成分除去精度、空間的バランスを記録し、「前処理完了確認（ID別）」で各IDの最終出力と完了状態を確認する。
8. リポジトリの変更を検証し、対象ファイルだけをcommitして個人リポジトリへpushする。
9. pushとNotionの読み戻し確認が完了してから、利用者へ結果を共有する。

本番一括処理へ進む前に、パイロットIDでスクリプト、パラメータ、完了条件を確定します。確定後は同じ版を全IDへ適用し、IDごとに処理を変えません。正常完了したIDを理由なく再処理せず、再処理は実装不具合、出力欠損、または合意済み仕様変更がある場合に限ります。

Notionの `解析ストーリー` は、対象IDの採否と例外処理に関するライブの正本です。過去の会話、キャッシュ、以前の集計だけで解析対象を決めません。

新しい恒常ルール、解析方針、作業結果が確定した場合は、個別の指示を待たず、その作業の一部として対応するGitHub文書とNotionページを更新します。

## Phase 1本番実行の最重要事項

Phase 1の試行実行・本番実行では、次を必ず守ります。詳細なチェックリストは[Phase 1実行README](解析プログラム/Phase1_脳波前処理/README.md)を正本とします。

1. 実行の直前に、このREADME、運用ルール、解析上の注意事項、Phase 1仕様書、Notionの解析ストーリー配下を読み直す。
2. 全IDを、GitHubで確定した同一のPythonスクリプトの実行だけで処理する。CodexがIDごとに探索的な計算、手作業の代替処理、都合のよいコード変更を行わない。
3. Python実行、出力確認、Notion記録、HTML・topomap確認、Computer Useを含む通常の前処理工程では利用者承認を求めず、ID単位の工程を最後まで完了する。許可範囲外、安全上の問題、または自力で解決できない真の阻害要因がある場合だけ停止して報告する。
4. 実行成功だけで完了とせず、指定先の全出力、HDF5の読み戻し、QC HTML、Notionの「ICA処理結果（ID別）」「前処理完了確認（ID別）」、解析記録まで確認・更新する。
5. Computer UseでHTML等を開いた場合は、確認終了後に必ず閉じる。
6. 各IDで、確定パラメータ、入力・出力先、命名、除外mask、分割IDの扱い、QC方法が仕様どおりか確認する。

Phase 1は、ID101によるパイロット検証と絶対振幅400 µVの確定後、ID102以降を含む本番処理を完了しました。解析対象40名・2セッション、合計80セッションIDを同一の確定スクリプトで処理し、ID130／230はこの80 IDに含めていません。

## Phase 2行動データ解析の完了状態

Phase 2のNo1（RT解析）とNo2（ミスタッチ解析）は、解析対象40被験者ペアへ同一の確定Pythonスクリプトを適用します。No1は200 ms未満のRTだけを除外し、個人RT推移、30試行幅・50試行幅の製品群別Grand-average（平均±SEM）、`AllTrials`・`Last80Trials`のセット別RT定量化を作成します。Figure用フォルダはPNGだけとし、補助表とログは `tables/`・`logs/` へ分離します。このPNG-onlyのfigure運用はNo2とPhase 3にも適用します。再実行は、合意済みの仕様変更または成果物不具合がある場合に限ります。

## Phase 3瞬き解析の確定方針

Phase 3解析1は、Phase 1のセット別瞬き解析用HDF5からFp1・Fp2平均信号を主解析として瞬きイベントを検出し、Blink Rate時間変化とセット別定量化を行います。Fp1・Fp2単独は検出数の補助QCに限定します。検出確認HTMLはセッションID別、条件比較は被験者ペア別とし、Cキューブ群とVロートプレミアム群を分けます。現行実装の確定仕様と結果記録項目は[Phase 3 瞬き解析仕様](docs/Phase3_瞬き解析仕様.md)を正本とします。
