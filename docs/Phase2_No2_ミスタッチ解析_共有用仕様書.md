# Phase 2 No2：ミスタッチ解析 共有用仕様書

> **確定版（2026年10月3日）**：本書には、現行スクリプトで再現される最終決定事項だけを記載する。

## 1. 解析の目的

ガボール課題中のミスタッチ回数をセットごとに定量化し、目薬あり条件と目薬なし条件（Control）を比較する。

被験者は使用した目薬によりCキューブ群とVロートプレミアム群に分け、2製品群を混合せず、各群内で同一被験者の2条件を対応付ける。

## 2. 解析の概要

生の行動results CSVにある `ResponseType = mistouch` を候補とする。ただし、キーの連続押しにより複数行へ分かれた記録を複数回と数えないよう、実測した時間間隔に基づいて同一操作を統合する。

最終的には、各被験者・各条件・各セットの確定ミスタッチ回数を求め、製品群ごとにSet 1〜6の対応あり比較を可視化する。推測統計は行わず、記述統計とfigureを出力する。

## 3. 解析の流れと確定設定

### 3.1 被験者・条件の対応付け

- 1回目ID、2回目ID、目薬ありID、使用製品を匿名化された被験者対応表から確定する。
- IDの番号帯から条件を推測しない。
- 全被験者を同一のPythonスクリプト内のループで処理し、被験者ごとに基準を変更しない。

**理由：** 同一被験者の2条件を正しく対応させ、製品群と条件の割付誤りを防ぐため。

### 3.2 入力データ

- 入力：各セッションの `*_block1_results.csv`〜`*_block6_results.csv`
- 使用列：`ResponseType`、非Sysの `KeyPress(ms)`、`TiltOnset(ms)`、`Block`
- ミスタッチ候補：`ResponseType = mistouch`
- 正答イベント：`ResponseType = correct`
- 時刻単位：ミリ秒
- 集計単位：被験者ペア×条件×セット
- セット境界またはファイル境界を越えてイベントを統合しない。

分割・再開始記録では、No1と同じ完成セットの選択規則を使用する。ミスタッチの時系列を安全に一意化できないセットを推定で補わない。

**理由：** ミスタッチの統合にはイベントの時系列順が必要であり、異なるセットや不確かな記録片を接続すると回数を誤るため。

### 3.3 ミスタッチイベントの確定

基本は、mistouch 1行を1回のミスタッチとする。同一セット内を時系列順に処理し、次の例外だけを同一操作として統合する。

| 規則 | 確定条件 | 処理 |
|---|---|---|
| 連続mistouch | 他イベントを挟まない隣接mistouchの `KeyPress(ms)` 差が0〜50 ms | 1回へ統合 |
| correctを挟む連続押し | `mistouch → correct → mistouch` の3行で、外側mistouch間が0〜100 ms、かつcorrectのRTが50 ms以下 | 1回へ統合 |
| その他 | 上記のいずれにも該当しない | 別のミスタッチとして数える |

correctのRTは次式で確認する。

```text
Correct RT [ms] = KeyPress(ms) - TiltOnset(ms)
```

- 50 msまたは100 msと等しい場合も統合対象とする。
- correctを挟む規則は、間のcorrectがちょうど1行の場合だけ適用する。
- 先頭から順に統合し、すでに統合済みのmistouch行を重複して数えない。
- 時刻欠損または時刻逆転がある行を自動的に統合しない。
- No1で採用した「RTが200 ms未満ならRT解析から除外する」規則は、No2のイベント分類には適用しない。`ResponseType = correct` の行は、RTが200 ms未満という理由だけでmistouchへ再分類しない。
- ただし、上記の `mistouch → correct → mistouch` 例外に該当するcorrectは、有効RTとして使うのではなく、連続押しの途中で刺激が提示された可能性を判断する材料として使用する。

**理由：** 目的は、連続押しによる反復記録を1回へまとめる一方、時間を空けた別の押下を残すことである。

### 3.4 時間閾値の根拠

- 全ID・全セットで確認した隣接mistouch間隔17,796件のうち、17,107件（96.1%）が50 ms以内だったため、連続mistouchの境界を50 msとした。
- mistouch間が100 ms以下でcorrectを挟む453例は、すべてcorrectが1行だけで、そのRTは0〜48 msだった。この実測構造に基づき、correctを挟む例外規則を設定した。

**理由：** キー入力の固定サンプリング周波数が記録されていないため、実データの時間間隔分布を用いて連続押しの境界を定めた。

### 3.5 EEG欠損セットの反映

Phase 1でEEG欠損と確定したセットは、後続のEEG解析と比較単位を揃えるためNo2でも使用しない。

- 対象：ID 109 Set 1、ID 120 Set 6、ID 135 Set 2、ID 225 Set 4
- 該当する被験者ペアでは、目薬あり・Controlの両条件を同じセットでNaNとする。
- 該当セットはドット、接続線、被験者間平均、SD、有効人数Nから除外する。
- 欠損値の補間や前詰めは行わない。

**理由：** 被験者内比較の対応を保ち、行動解析とEEG解析で使用するセットを一致させるため。

### 3.6 セット別集計

各被験者・各条件・各セットについて、統合後のミスタッチ回数を1つの定量値とする。製品群×Setごとに、次を算出する。

- Eye Dropの被験者間平均と標本SD（`ddof=1`）
- Controlの被験者間平均と標本SD（`ddof=1`）
- 両条件が有効な被験者数N
- 対応差の平均（Eye Drop − Control）

試行やmistouch行を被験者間で直接プールせず、被験者を解析単位とする。推測統計と有意差判定は実施しない。

**理由：** 同一被験者の条件対応を保ったまま、セットごとの条件差と被験者間のばらつきを示すため。

### 3.7 Figure

製品群ごとに1枚を作成し、Set 1〜6を独立した6パネルとして横一列に配置する。

- 左：`Eye Drop (C Cube)` または `Eye Drop (V Rohto Premium)`
- 右：`Control`
- バー：条件内の被験者間平均
- ドット：各被験者の確定ミスタッチ回数
- 接続線：同一被験者の2条件
- 縦軸：`Mistouch (count)`、下限0、整数目盛り
- 6パネルで共通の縦軸スケール
- フォント：Arial、表記：英語
- バー中心：`-0.32`、`0.32`
- バー幅：`0.42`
- 横軸範囲：`-0.90`〜`0.90`
- ドットサイズ：`150`
- ドット横ずらし：各中心から最大±`0.055`

No1と区別するため、No2では条件色を一段暗く固定する。

| 条件 | 色 |
|---|---|
| Control | `#402B5D` |
| Cキューブ | `#963838` |
| Vロートプレミアム | `#AC6820` |

ドットは条件色へ透過を加えて白枠を付け、バーには細い黒枠を付ける。

**理由：** No1のセット別定量化と読み方を統一しつつ、RTとミスタッチのfigureを視覚的に区別するため。

### 3.8 Cキューブ群の感度分析

主解析では、ID132-232の目薬ありSet 1の確定ミスタッチ375回を除外しない。この値は50 ms以内の自動リピートではなく、セット全体に分布する間隔押しとして記録されている。

追加の感度分析では、結果依存の片条件除外を避けるため、ID132-232のSet 1をEye Drop・Controlの両条件ともNaNとする。Set 2〜6と他被験者は変更しない。

### 3.9 対応あり検定と全Set統合

- 各SetでEye Drop対Controlの両側対応ありt検定を行う。
- 製品群・解析版ごとに6つの両側対応ありt検定を行い、主PNGは未補正p値を表示する。
- 6パネルfigureは未補正p値を表示するPNGを1枚だけ保存する。最大定量値を `M` として、黒いブラケットを `1.14M`、アスタリスクの基準中心を `1.18M`、`n.s.`の基準中心を `1.20M`、Set名の中心を `1.27M`、縦軸上限を `1.33M` に置く。`*`（p<0.05）、`**`（p<0.01）、`***`（p<0.001）、`n.s.`を表示し、`n.s.`は30 pt、アスタリスクは42 ptとする。それぞれを独立に制御して統計線からの見かけの距離を揃え、Set名・統計文字・軸ラベルはArialに統一する。縦軸は切りのよい間隔を選び、0を含む目盛数字を3～6個とする。補正後p値はCSVにのみ保存する。
- 各被験者について、両条件で利用可能な全Setの確定ミスタッチ回数を合計し、全Set統合値とする。比較は1つだけなので多重比較補正は行わない。
- 主解析と感度分析の全Set統合値・統計・figureも別々に保存する。
- 統計CSVには未補正p値、Bonferroni・Holm・FDR補正後p値、t値、自由度、対応人数、平均差、差の95%信頼区間、Cohen's dzを保存する。

**理由：** 主解析の定義を維持しつつ、極端値がCキューブ群Set 1の要約へ与える影響を確認するため。感度分析は主解析の置き換えではない。

### 3.9 品質記録

セッション・セットごとに次を保存する。

- 元mistouch行数
- 確定ミスタッチ回数
- 50 ms規則で統合したリンク数
- correctを挟む100 ms規則で統合したリンク数
- `KeyPress(ms)` 欠損行数
- 時刻逆転数
- 入力元ファイルとEEG欠損セット

**理由：** 元行数から最終回数へ至る処理を追跡し、イベント統合とデータ品質を後から検証できるようにするため。

## 4. 出力

実行スクリプト：

```text
解析プログラム/Phase2_行動データ解析/Phase2_No2_Mistouch.py
```

指定OneDriveの次の場所へ保存する。

```text
Phase2_行動データ解析/
└── No2_Mistouch/
    ├── CCube/
    │   ├── 主解析figure PNG
    │   └── ID132-232 Set 1除外の感度分析figure PNG
    ├── VRohtoPremium/
    │   └── 主解析figure PNG
    ├── Sub/
    │   ├── 被験者別セット値CSV

    │   └── 感度分析の補助CSV・JSON
```

製品群フォルダはFigure閲覧用としてPNGだけを置く。Figure以外の補助成果物は `Sub/` へまとめ、全体の完了ペアと実行状態を記録するバッチ要約だけをNo2直下へ置く。

## 5. 再現性

被験者対応は、次の4列を持つ非公開manifestから読み込む。

```text
first_session_id, second_session_id, drops_session_id, product
```

同一manifestと同一スクリプトを用いて全被験者を一括処理する。条件対応、各規則による統合件数、EEG欠損セット、入力異常、出力完了状態をNotionへ記録する。
