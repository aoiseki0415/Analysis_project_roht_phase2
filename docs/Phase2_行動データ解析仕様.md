# Phase 2 行動データ解析仕様

## 1. 適用範囲

Phase 2では、ガボール課題の行動データから反応時間（RT）とミスタッチを解析します。Cキューブ群とVロートプレミアム群を分け、各群内で同一被験者の目薬あり条件とコントロールを比較します。

本書は、解析1（No1）のRT試行進行解析・セット別RT定量化と、解析2（No2）のミスタッチ解析の確定仕様を示します。推測統計は実施せず、No2でもPhase 1のEEG欠損セットを被験者内で対応付けます。

## 2. 解析1（No1）：RTの試行進行解析

### 2.1 入力

- Phase 1のHDF5ではなく、生の行動データにある `*_block1_results.csv` から `*_block6_results.csv` を使用します。
- 目薬の種類、目薬あり・なしのセッション対応、実施順は、許可されたGoogleスプレッドシートとNotionの被験者・セッションID対応表を正本として確認します。
- 練習試行は含めません。
- 分割記録のあるID 109、120、135、225も個人別解析の対象とします。候補となる行動results CSVをすべて確認し、各セットで重複のない320刺激試行を確定します。
- 全員実行で必要試行の欠損・競合を解消できない場合は、当該セッションだけでなく対応する被験者ペア全体をNo1から除外し、理由をバッチ実行要約とNotion結果表へ記録します。他の被験者の処理は同じコードで継続します。
- 再開始等で同じTrialが複数記録に存在する場合は二重計上せず、320試行が完了した記録を優先します。分割片を用いる必要がある場合は、Trial番号と元ファイルを保持して、重複のない1〜320を再構成します。欠損を補間または推定して320試行を作りません。
- Phase 1でEEG欠損のため除外したセットに合わせ、個人解析ではID 109のSet 1、ID 120のSet 6、ID 135のSet 2、ID 225のSet 4を全320試行NaNにします。個人figureでは、同じ被験者の対応するもう一方のセッションは通常どおり描画します。
- Grand-averageでは被験者内対応を保つため、上記4ペアの該当セットを両条件ともNaNにしてから集計します。欠損セット以外は通常どおり採用します。
- 被験者の2セッションID、製品群、目薬ありの実施回は、Google Driveの `実験本解析_Codex共有用 / 【rht-mvp01】被験者リスト （これはコピーです） / 共有用（匿名）` を実行前に確認します。100番台／200番台だけから条件を推測しません。
- No1は、被験者対応を入力として受け取り、同じPythonコード内のループで全被験者を処理できる設計にします。被験者ごとのコード複製・手修正・場当たり的な分岐を行いません。

### 2.2 RTの算出

RTは、各刺激試行について必ず次式で再計算します。

```text
RT [ms] = KeyPress(ms) - TiltOnset(ms)
```

- `TiltOnsetSys(ms)` と `KeyPressSys(ms)` はPhase 2のRT算出に使用しません。
- 両入力列はミリ秒単位なので、差分もミリ秒です。EEGのサンプリング周波数はこの計算に関係しません。
- 再計算値とCSVの `RT(ms)` を照合し、不一致数と最大差を品質記録へ残します。
- ミスタッチ行はRT算出対象に含めません。

### 2.3 試行数の検証

- 各セットについて、刺激試行が320件、Trialが320種類、算出可能なRTが320件であることを別々に確認します。
- ミスタッチ行が追加されるため、CSV全体の行数は320を超えて構いません。
- 重複Trial、欠損RT、320件以外の刺激試行、不明なResponseTypeがあれば、そのセッションを自動的に正常扱いせず、結果表へ記録します。

### 2.4 EEG欠損セットとRT外れ値

- 行動データ自体に320試行が存在していても、Phase 1でEEG欠損と確定したセットは外れ値計算より先に全試行をNaN化します。対象はID 109 Set 1、ID 120 Set 6、ID 135 Set 2、ID 225 Set 4です。
- 外れ値基準は、1セッションIDについて、EEG欠損セットをNaN化した後に残る全セットの有限RTから求めます。通常セッションは6セット、上記4セッションは5セットが基準になります。
- 標準偏差は、従来のMATLAB `std` と同じ標本標準偏差（`ddof=1`）を使用します。
- 平均を `mean_RT`、標準偏差を `SD_RT` とし、`mean_RT ± 2 × SD_RT` の範囲外を除外します。
- 境界値と同じRTは残し、範囲を厳密に下回る、または上回るRTだけを除外します。
- 除外した試行の位置は詰めず、RT値をNaNに置き換えます。Trial番号と320点の並びは維持します。
- セッションごとに、EEG欠損セット、解析使用セット数、平均、SD、2SD下限、2SD上限、外れ値除外件数、除外Trial、除外後の有効RT数を記録します。EEG欠損による320試行と2SD外れ値を混同しません。

### 2.5 移動平均

- 各セットを独立に処理し、セット境界をまたいで平滑化しません。
- 20試行幅のGaussian重み付き移動平均を使用します。
- GaussianのFWHM（半値全幅）は9試行、対応する標準偏差は `9 / 2.35482 ≒ 3.82` 試行です。
- 20試行の範囲は、Trial `i` に対して原則 `i-10` から `i+9` とします。Trial 1では1〜10、Trial 2では1〜11、Trial 11で初めて1〜20を使用し、終端側も対称の考え方で利用可能範囲へ短縮します。
- 端点では存在する試行だけを使い、Gaussian重みの合計が1になるよう再正規化します。
- 窓内のNaNには重みを与えず、残った有効RTの重みを再正規化して平均します。窓内がすべてNaNの場合だけ出力をNaNにします。
- 出力位置は各セット320点のまま維持し、欠損除外後のデータを前詰めしません。

持続的注意研究では、複数のgradCPT/CPT研究でGaussian kernelが反復採用され、FWHM 9試行・周辺20試行、7〜7.2秒などの設定が報告されています。固定時間ビンや3〜25試行の単純移動平均も使われますが、目的ごとに幅が異なり、30試行を標準とする一貫した根拠は確認できませんでした。本解析は瞬間的な注意状態の分類ではなく、RT平均の局所推移を可視化する目的であるため、複数研究で主要なGaussian型を採用し、その中で本課題に最も近い20試行・FWHM 9試行を使用します。調査過程と限界は [Phase 2 RT移動平均 文献調査](Phase2_RT移動平均文献調査.md) に残します。

### 2.6 被験者別出力

- 各被験者について、目薬ありセッションとコントロールセッションを対応付けます。
- 解析・成果物・Notion記録の単位はセッションID単独ではなく、同一被験者の2セッションIDを組み合わせた `ID<1回目>-<2回目>` とします。
- 横軸は、各セット内のTrial 1〜320を1〜100%へ線形変換したうえで、Set 1〜6を累積0〜600の一つの連続軸へ順番に連結します。Set 1は0〜100、Set 2は100〜200、以降も同様にSet 6の600までを示します。
- 横軸名は **`Experimental Progress, %`** とし、0〜600を50刻みの通常目盛りで表示します。数字の個別移動は行わず、すべて同じ高さ・同じ文字サイズとし、各目盛りの短い線も通常どおり表示します。
- セット間へグレーの点線を入れ、各セット区間の上部かつ縦軸上限より内側に `Set 1`〜`Set 6` を表示します。
- 移動平均の計算自体はセットごとに独立させますが、figureでは各条件のSet 1〜6の線を連続して描画します。
- 縦軸名は **`Reaction Time (ms)`** とします。
- 縦軸の下限は必ず0 msとします。上限は、両条件の移動平均の最大値がおおむね縦軸の70%位置になる値を100 ms単位で切り上げ、上側に十分な余白を確保します。移動平均の最小値は、データ分布が許す範囲でおおむね20%位置となることを目安とします。
- 目薬あり条件とコントロールの移動平均を同一figureへ描きます。
- figure内の文字はすべて英語とし、フォントは過去MATLAB実装と同じArialを使用します。軸名28 pt、目盛り20 pt、凡例18〜20 pt、主要線3 ptを標準とし、出力サイズに応じても可読性を下げません。
- 色は全解析で固定し、コントロールを暗い紫 `#563A7C`、Cキューブを赤 `#C84A4A`、Vロートプレミアムをオレンジ `#E58A2B` とします。凡例は `Control` と製品群に応じた `Eye Drop (C Cube)` または `Eye Drop (V Rohto Premium)` とし、図本体から離して上側へ配置します。
- y方向のグリッド線・基準線は表示しません。セット境界を示す縦方向のグレー点線だけを残します。
- y軸の目盛りは、0 msから500 ms刻みの切りのよい数値を使用し、通常は5〜6個程度を表示します。上限値が500 ms刻みでない場合は、上端を余白として残します。
- `Participant 101` 等のfigureタイトルは付けません。figureには、軸名、単位、色・線種の意味、凡例、セット境界を明記します。
- 個人別解析の後、同じNo1内で製品群別のGrand-averageを作成します。Grand-averageでは被験者間平均を線で示し、同じ色の薄い帯で平均±1 SDを示しますが、凡例のタイトルに `Mean ± 1 SD` は表示しません。
- Grand-averageは、各セッションの外れ値処理とGaussian移動平均が完了した後の個人別320点を、同じセット・同じ進捗位置で被験者間平均します。生RTを被験者間で先に連結・平均してから平滑化しません。
- Grand-averageの対象者は実行時の非公開manifestに列挙された被験者ペアとします。EEG欠損セットの確定表は全員共通スクリプトへ固定し、該当する被験者ペアでは、分割セッション側だけでなく対応するもう一方の条件も同じセットをNaN化します。個人figureにはこの対称化を適用しません。
- Grand-averageはCキューブ群とVロートプレミアム群を別々に作成し、目薬あり条件とコントロールを混合しません。各進捗位置で平均、標本SD（`ddof=1`）、有効人数Nを条件別に算出します。欠測値は前詰め・補間せず、その位置の有限値だけで集計します。
- Grand-average figureは個人figureと同じ0〜600の横軸、固定色、軸・文字仕様を用い、平均線と平均±1 SDの薄い帯を表示します。縦軸は製品群間で統一し、Cキューブ群・Vロートプレミアム群とも **0〜1800 ms** に固定します。

### 2.7 セット別RT定量化

- Cキューブ群とVロートプレミアム群を分け、各製品群についてSet 1〜6の結果を作成します。
- 被験者ごとのセット別定量値は、**移動平均後の値ではなく**、EEG欠損セットのNaN化と2SD外れ値除外が完了した試行別 `RT_clean_ms` の算術平均とします。NaNは平均計算から除外し、残った有限試行だけを用います。
- 現時点ではセット内の全有効試行の平均RTを代表値としますが、代表値の定義は要検討事項として保持します。
- EEG欠損セットを持つ4ペアでは、Grand-averageと同じ被験者内対応を使用します。該当セッションだけでなく、対応するもう一方の条件も同じセットをNaNとし、そのセットの両条件の定量値を欠損にします。
- 製品群ごとに1枚のfigureを作り、Set 1〜6を独立した6パネルとして横一列に配置します。6セットを連続軸として接続しません。
- 各パネルは左を `Eye Drop (C Cube)` または `Eye Drop (V Rohto Premium)`、右を `Control` とし、条件内の被験者間平均をバーで示します。
- 各被験者のセット別平均RTをドットで重ね、同一被験者の2条件を線で接続します。EEG欠損により両条件をNaN化した被験者は、そのセットのドットと接続線へ含めません。
- バー、ドット、接続線の集計単位は被験者とし、試行を被験者間で直接プールしません。
- 色は既存No1と同じく、Control `#563A7C`、C Cube `#C84A4A`、V Rohto Premium `#E58A2B` に固定します。ドットはバーより透明にし、白い枠線を付けます。バーは細い黒枠を使用します。
- 各パネルの2本のバーは中央付近でわずかに間隔を空け、中心を `-0.32` と `0.32`、幅を `0.42` とします。横軸範囲を `-0.90`〜`0.90` に固定して左右端へ余白を確保し、短い目盛り線もバー中心と一致させます。被験者ドットはサイズ150、横方向のずらし幅は各中心から最大±0.055とします。
- figure内はArial・英語表記とし、各パネルへ `Set 1`〜`Set 6` を縦軸上限より内側に表示します。縦軸は6パネルで共通の `Reaction Time (ms)` とし、下限を0 ms、目盛りを500 ms刻みにします。縦軸の数字は全6パネルに表示し、横軸の条件名22 pt、括弧内の目薬名18 pt、縦軸数字23 pt、Set名26 pt、縦軸名30 ptを標準とします。
- OneDriveの各製品群配下へ `SetMeanQuantification/` を作成し、6パネルfigure、被験者別セット定量値CSV、製品群×Set集計CSV、実行要約JSONを保存します。
- 既存の `Individual/` と `GrandAverage/` の移動平均成果物は再生成・上書きしません。定量化だけを実行する専用オプションを使用します。
- 推測統計の手法は未定です。今回の出力には検定結果や有意差記号を追加しません。

## 3. 解析2（No2）：ミスタッチ解析

### 3.1 入力と比較単位

- Phase 1のHDF5ではなく、生の行動データにある `*_block1_results.csv` から `*_block6_results.csv` を使用します。
- `ResponseType` が `mistouch` の行をミスタッチ候補、`correct` の行を正答イベントとして扱います。
- 時刻差の判定には非Sys列の `KeyPress(ms)` を使用します。単位はミリ秒です。
- 製品群、目薬あり・なしのセッション、実施順は、許可されたGoogleスプレッドシートとNotionの被験者・セッションID対応表で確認します。100番台／200番台から条件を推測しません。
- Cキューブ群とVロートプレミアム群を分け、各群内で同一被験者の目薬あり条件とコントロールを比較します。
- 集計単位は被験者ペアとセットです。セット境界や別ファイルの境界をまたいでミスタッチを結合しません。
- 全被験者を同じPythonコード内のループで処理し、被験者別に判定基準やコードを変更しません。

### 3.2 ミスタッチの確定規則

基本は、`ResponseType = mistouch` の1行を1回のミスタッチとします。ただし、同一セット内で時系列順に次の規則を適用します。

1. **連続mistouchの結合**：隣接する2つのmistouch行の間に他のイベントがなく、`KeyPress(ms)` の差が **50 ms以下**なら、同じミスタッチ操作として1回にまとめます。
2. **correctを1行挟む例外結合**：mistouchと次のmistouchの間に `correct` が**ちょうど1行**あり、最初と次のmistouchの `KeyPress(ms)` 差が **100 ms以下**、かつ挟まれたcorrectのRTが **50 ms以下**なら、3行全体を同じミスタッチ操作として1回にまとめます。correctのRTはNo1と同じく `KeyPress(ms) - TiltOnset(ms)` で確認します。
3. 上記に当てはまらないmistouchは、別々のミスタッチとして数えます。50 msまたは100 msとちょうど等しい場合は結合対象です。

結合は先頭から時系列順に行い、一度同じイベントへまとめたmistouch行を重複して数えません。入力行、元ファイル、セット、時刻、適用規則を追跡可能にし、欠損時刻や時刻逆転を自動的に結合しません。

### 3.3 閾値の根拠と品質記録

- 全ID・全セットで隣接mistouch間隔を確認したところ、**17,796間隔中17,107間隔（96.1%）が50 ms以内**でした。この実測分布に基づき、連続mistouchを同一操作とみなす境界を50 msに設定します。
- mistouch間にcorrectが入り、mistouch同士の間隔が100 ms以下だった453例は、すべてcorrectが1行だけでした。そのcorrectのRTは0〜48 msで、すべて50 ms以下でした。この実測構造に基づき、例外規則を「correct 1行・mistouch間100 ms以下・correct RT 50 ms以下」とします。
- セッション・セットごとに、元mistouch行数、確定ミスタッチ回数、50 ms規則で結合した件数、correctを挟む100 ms規則で結合した件数、時刻欠損・逆転・未分類件数を記録します。
- No2のイベント結合はミスタッチ回数を定義するための処理です。No1のRTデータや既存成果物を変更しません。

### 3.4 セット別定量化とFigure

- 被験者ごと・条件ごと・Set 1〜6ごとに、確定したミスタッチ回数を1つの定量値とします。
- 製品群ごとに1枚のfigureを作り、Set 1〜6を独立した6パネルとして横一列に配置します。6セットを連続軸として接続しません。
- 各パネルは左を `Eye Drop (C Cube)` または `Eye Drop (V Rohto Premium)`、右を `Control` とします。バーは条件内の被験者間平均、ドットは各被験者の回数、接続線は同一被験者の2条件の対応を示します。
- 縦軸名は **`Mistouch (count)`** とし、下限は0、目盛りは整数とします。縦軸スケールは同一figure内の6パネルで統一し、最大値とドットが隠れない上側余白を確保します。
- Figureの構成、バー中心、バー幅、横軸余白、ドットサイズ、文字サイズ、Arial、条件名、Set名の配置はNo1のセット別RT定量化と同じにします。
- No1との識別性を保つため、No2では条件色を一段暗く固定します。Controlは `#402B5D`、C Cubeは `#963838`、V Rohto Premiumは `#AC6820` とします。ドットは同じ条件色へ透過を加え、白枠を付けます。バーには細い黒枠を使用します。
- 推測統計の手法は未定です。現段階では検定結果や有意差記号を表示しません。

### 3.5 結果記録と未確定事項

NotionのNo2結果表は1被験者ペア1行とし、少なくとも次を記録します。

- 1回目IDと2回目ID、製品群、目薬使用回、目薬ありID、コントロールID
- 両条件・各セットの元mistouch行数と確定ミスタッチ回数
- 両条件の50 ms規則による結合件数と、correctを挟む100 ms規則による結合件数
- 時刻欠損、時刻逆転、未分類イベント、入力ファイルの不整合などの備考
- OneDrive出力の完了状態

## 4. No1のファイル対応

- Python：`解析プログラム/Phase2_行動データ解析/Phase2_No1_ReactionTime.py`
- OneDrive：`Phase2_行動データ解析/No1_ReactionTime/`

OneDriveのNo1配下では、`CCube` と `VRohtoPremium` を分け、各製品群の中に被験者別成果物、`GrandAverage`、`SetMeanQuantification`を置きます。被験者別フォルダとファイル名は、単独IDではなく `ID<1回目>-<2回目>` を使用します。

No1は、ローカルデスクトップの `解析に必要なデータたち/` へ加工済み・中間データを保存しません。個人別figure、QC要約、実行ログ、将来のGrand-averageは指定OneDriveだけへ保存します。試行別の `RT_TrialData.csv` は保存しません。

Grand-averageは同じスクリプトへ `--grand-average --skip-invalid-participants` を付けて実行します。製品群ごとの `GrandAverage/` にfigure、同一進捗位置の平均・SD・Nを収めたCSV、実行要約JSONを保存します。No1直下のバッチ実行要約JSONに、完了ペア、除外ペア、除外理由、Grand-average出力を保存します。

## 5. No1の文献上の位置づけ

- FortenbaughらのgradCPT再現研究では、試行ごとのRT変動指標をGaussian kernel（FWHM 9試行）で平滑化し、周辺20試行の情報を重み付けしていました。
- Teramotoらは、持続的注意のVTCにGaussian kernel（FWHM 7秒）を使用しました。
- van LeeuwenらのSMART法は、trialごとに1点得られる反応データの時間推移に対し、Gaussian kernelと時点ごとの重み正規化を用いる方法を示しています。
- これらは主としてRT変動や一般的な反応時系列を扱う方法であり、本解析の生RT平均と完全に同一の目的ではありません。そのため、20試行・FWHM 9試行は先行研究に整合する可視化設定として採用し、推測上の唯一解とは扱いません。

網羅的な比較表、代替法、採否理由は [Phase 2 RT移動平均 文献調査](Phase2_RT移動平均文献調査.md) を参照します。
