# Phase 1 脳波前処理仕様

## 1. 目的と成果物

Phase 1の目的は、各セッションの連続EEGを自動で前処理し、**1ブロックを1つの論理データセット**として全6ブロック分を保存することです。正常なブロックは1つのFIF、記録中断を含むブロックは複数の連続区間と欠測情報をまとめた1つのブロック用パッケージとして扱い、存在しない信号を補間して連続化しません。

保存先は、Mac miniの次の許可済み領域です。

```text

  Phase1_脳波前処理/
```

目視確認用figure、表、品質管理ログは、指定OneDriveの次の領域へ保存します。

```text
実験本番_本解析/Phase1_脳波前処理/
```

## 2. 実データで確認した入力仕様

- EEG CSVは1行目が記録メタデータ、2行目が列名です。
- EEGは32チャンネル、256 Hzです。
- `EEG.<電極名>` の単位はµVです。ただし、全ファイルで値域、欠損、連続0、非数を毎回検査します。
- `EEG.Interpolated` はCortexが補間したサンプルを示すため、割合を品質指標として保存します。
- JSONとintervalMarkerは課題イベントの必須入力にしません。
- 課題イベントとブロック境界は行動側の `events.csv`、試行時刻はblock結果CSVから取得します。

## 3. 時刻同期の決定

### 3.1 採用する時刻

- EEG：補正済みの `Timestamp`（秒）
- 行動イベント：`SysUnixTime(ms)` を1000で割った秒
- 刺激と回答：`TiltOnsetSys(ms)`、`KeyPressSys(ms)` を1000で割った秒
- `OriginalTimestamp`：同期の主軸にはせず、監査用に保持

EmotivPROは記録終了後、等間隔サンプリングを利用して `Timestamp` を補正します。`OriginalTimestamp` はリアルタイム算出値です。代表IDと分割対象IDの実測でも、`Timestamp` は256 Hz相当の約3.906 ms間隔で安定していました。旧MATLAB実装の `OriginalTimestamp` 使用は参考として残しますが、本解析では補正済み `Timestamp` を優先します。

### 3.2 同期検証

1. `Timestamp` が単調増加し、隣接差が256 Hzと整合することを確認する。
2. EEG記録範囲と行動イベント範囲の重なりを確認する。
3. 各イベントを最も近いEEGサンプルへ対応付ける。
4. 対応誤差は原則として0.5サンプル以内、すなわち約1.953 ms以内とする。
5. 対応できないイベント、重複したブロック境界、範囲外イベントがあれば自動処理を成功扱いにせず、品質管理結果へ記録する。

ID 101、109、120、135、225のブロック境界を試験した結果、記録範囲内に存在する境界の最近傍誤差は最大1.948 msでした。ID 135のブロック2終了境界はEEGの記録中断中にあり、対応サンプルが存在しません。

## 4. 分割記録とブロック化

- 記録分割は、ファイル順ではなく `Timestamp` で並べます。
- 記録間の空白を補間しません。
- フィルタ端効果とICAの安定性のため、原則として各取得区間を連続データとして前処理し、セッション全体の利用可能区間で1つのICAを推定してから、`block_start` と `block_end` でブロックへ切り分けます。
- ICAは時間順序そのものをモデル化しないため、欠測を除外した複数区間をICA学習へ利用できます。ただし、区間境界をまたいだフィルタ処理は行いません。
- 途中でブロックを最初からやり直した記録が見つかった場合は、完了した後半のブロックだけを採用します。それ以外の中断パターンは自動置換せず、欠測として保持します。

実データでは、次のブロックに記録内欠測があります。

| ID | 影響ブロック | 確認した状態 |
|---|---:|---|
| 109 | 1 | ブロック途中に記録間の空白あり |
| 120 | 6 | ブロック開始後に記録間の空白あり |
| 135 | 2 | 前半記録がブロック途中で終了し、後半記録はブロック3前から再開 |
| 225 | 4 | ブロック途中に記録間の空白あり |

これら4ブロックは前処理データを作成して欠測範囲を明示しますが、Phase 3・4の統計解析へ含めるかは未確定です。欠測を連続波形として埋めることは禁止します。

## 5. 前処理の順序

1. **入力監査**：ヘッダー、チャンネル、256 Hz、単位、時刻、非数、連続0、`EEG.Interpolated`、イベント範囲をセッションごとに検査する。
2. **取得区間の構成**：分割ファイルを時刻順に整理し、空白を欠測として保持する。
3. **連続0の検出**：5秒以上のflatlineを初期候補とする。対象チャンネルと時間範囲を記録する。
4. **フィルタ**：1–100 Hzを基本帯域とし、50 Hzと100 Hzにノッチフィルタを適用する。各取得区間で独立に処理し、区間境界をまたがない。
5. **トレンド除去の確認**：線形トレンド除去後の全体波形と縮約表示をOneDriveへ出力する。1 Hz高域通過との重複効果はパイロットで確認する。
6. **平均基準化**：不良チャンネル判定後、ICA用データを共通平均基準へ変換する。除去チャンネルとデータランクを保存する。
7. **ICA前の自動品質処理**：不良チャンネルと大振幅の不良時間区間を自動検出する。可能な限り時間区間の除外を優先するが、長時間にわたり不良なチャンネルは除去する。
8. **ICA**：1–100 Hz、共通平均基準のコピーに対し、固定乱数シードのextended Infomaxをセッション単位で実行する。
9. **瞬き成分の自動選択**：下記の規則で瞬き成分だけを選び、最終EEGから除去する。他のICLabel分類は記録するが自動除去しない。
10. **ブロック化と保存**：前処理済みEEG、瞬きIC、品質情報をブロック1～6へ分けて保存する。

## 6. ICA前の自動品質処理

Google Driveの調査資料とEEGLAB `clean_rawdata` を基に、次を初期候補とします。これらは本番固定値ではなく、代表データで保持率と波形を評価してから確定します。

| 項目 | 初期候補 | 方針 |
|---|---:|---|
| FlatlineCriterion | 5秒 | 連続0・平坦チャンネル候補 |
| ChannelCriterion | 0.80 | 他チャンネルからの再構成との相関 |
| LineNoiseCriterion | 4 SD | 線雑音が過大なチャンネル候補 |
| ChannelCriterionMaxBadTime | 0.50 | 記録の50%以上で不良なら除去候補 |
| ASR BurstCriterion | 20 | ICA前の突発ノイズ検出の保守的な開始値 |
| WindowCriterion | 0.25 | 不良チャンネル比が25%を超える窓を除外候補 |
| WindowCriterionTolerances | `[-Inf, 7]` | 時間窓の外れ判定候補 |

Python環境には現時点で `pyprep` と `asrpy` を固定していません。EEGLABと同じ名称のパラメータをPython実装へ形式的に写すのではなく、候補ライブラリの再現性、除去率、時間情報の保持方法をパイロットで比較してから依存関係を追加します。処理後には、除去チャンネル、除去時間、残存時間、データランク、採用パラメータを機械可読ログへ必ず保存します。

## 7. 瞬きICA成分の完全自動選択

ICLabelの `eye blink` は有力な候補分類ですが、確率だけで「瞬きのみ」を保証しません。水平眼球運動等との混同を避けるため、次の複合条件を固定して自動判定します。

1. ICLabelの `eye blink` 確率が閾値以上。
2. Fp1・Fp2から作る前頭部瞬きproxyとIC時系列の相関が閾値以上。
3. Fp1・Fp2で同極性かつ前頭優位の頭皮分布を示す。左右逆極性が強い成分は水平眼球運動候補として除外する。
4. IC時系列に瞬き様の一過性ピークが存在し、イベント数と持続時間が生理的な範囲にある。
5. 候補が0個または過多、ICA未収束、ランク不整合の場合は、別成分を黙って除去せず、そのセッションを自動QC不合格として記録する。

初期値はICLabel `eye blink` 確率 **0.90** を推奨します。MNE-BIDS-Pipelineの既定0.80より保守的で、今回の目的である「瞬き成分だけを除去する」ことを優先した開始値です。前頭部相関、左右対称性、ピークの持続時間・回数、候補数上限は、複数の代表セッションで分布を確認してから固定します。本番運用では人が各成分を選択せず、固定済み規則で処理します。

## 8. 保存するデータと品質管理成果物

### ローカルのブロック別データ

- ICA適用後の前処理済みEEG
- 絶対 `Timestamp` とブロック内相対時刻
- 欠測区間と取得区間境界
- 使用・除去チャンネル

- 入力ファイル、処理パラメータ、ソフトウェア版、品質指標

### OneDriveの確認用成果物

- トレンド除去前後の全体波形と縮約波形
- ICA前後の同一区間・同一スケール比較
- 選択したICの頭皮分布、時系列、PSD、ICLabel確率
- 瞬き平均波形のICA前後比較
- 除去チャンネル、除去時間、データ保持率、ICA収束、候補数の一覧

## 9. 実装単位の案

- `Phase1_No1_InputAuditAndSynchronization.py`：入力監査、時刻同期、分割・欠測マニフェスト
- `Phase1_No2_AutomatedPreProcessing.py`：フィルタ、品質処理、ICA、瞬きIC除去、ブロック別保存、QC出力

No1で全セッションの入力と例外を確定し、その出力をNo2の唯一の入力台帳にします。

## 11. 実装前に確定する項目

1. 記録内欠測がある4ブロックを、後続のPhase 3・4の統計解析で除外するか。
2. ICA前区間処理で、ASRによる信号再構成を使うか、検出した窓を削除するか。本案件では削除を第一候補とする。
3. ICLabel 0.90、前頭部相関、左右対称性、ピーク持続時間・回数、候補数上限の最終値。
4. 不良チャンネルを除去したまま保存するか、最終段階で補間するか。現在は除去したまま保存する方針を第一候補とする。
5. 1 Hz高域通過に加えて明示的な線形detrendを維持するか。確認figureを比較して決定する。
