# フォルダ・ファイル管理

## 目的

解析スクリプト、加工済み・中間データ、figure・表・集計・ログを、同じフェーズ番号と解析番号で追跡できるようにします。

## 5フェーズ

| フェーズ | 内容 | フォルダ名 |
|---|---|---|
| Phase 1 | 脳波の前処理 | `Phase1_脳波前処理` |
| Phase 2 | 行動データの解析 | `Phase2_行動データ解析` |
| Phase 3 | 瞬きの解析 | `Phase3_瞬き解析` |
| Phase 4 | 脳波の解析 | `Phase4_脳波解析` |
| Phase 5 | 相関解析などその他 | `Phase5_相関・その他` |

各フェーズで、Cキューブ群とVロートプレミアム群を分け、それぞれについて目薬あり条件とコントロールを比較します。2製品を統合する解析は、目的と根拠を別途明記した場合に限ります。

## GitHub：解析スクリプト

ルート：`解析プログラム/`

スクリプトは該当フェーズのフォルダに置き、次の形式で命名します。

```text
Phase<フェーズ番号>_No<解析番号>_<内容>.py
```

例：

- `Phase1_No1_PreProcessing.py`
- `Phase2_No1_ReactionTime.py`
- `Phase3_No1_BlinkDetection.py`
- `Phase4_No1_SpectralAnalysis.py`
- `Phase5_No1_CorrelationAnalysis.py`

解析番号は各フェーズ内で1から採番します。既存Noの目的を変更して再利用せず、新しい解析は次のNoにします。完全に不要になったスクリプトだけを `解析プログラム（過去版いらなくなったやつ）/` へ移します。

## ローカル：加工済み・中間データ

ルート：

```text
/Users/aoiseki/Desktop/SandBox_ロート案件（データ）/解析に必要なデータたち/
```

生データ原本は常に読み取り専用です。上記の専用サブフォルダだけが書き込み可能です。

フェーズ配下に、必要に応じてスクリプトと対応するフォルダを作ります。

```text
Phase1_脳波前処理/

    Phase1_No1_input_manifest.parquet
  No2_AutomatedPreProcessing/
    IDxxx/
      Set1/
        IDxxx_Set1_brain_activity.h5
        IDxxx_Set1_blink_signal.h5
      Set2/
      ...
      Set6/
```

加工済みデータには、由来となる匿名ID、セット番号、処理段階、必要に応じて版や日付を含めます。主要データは、Eye成分除去後の脳活動解析用EEGと、除去Eye成分から得るFp1・Fp2・平均信号の瞬き解析用データの2種類とします。両方に、信号の各行と対応するセット内相対時刻、`OriginalTimestamp`、ICA学習除外区間mask、元チャンネル一覧、ICAから除外したチャンネルの32要素mask・名前・理由、同一セットの`results.csv`由来の行動データを含めます。行動データの同期時刻は`TiltOnsetSys(ms)`と`KeyPressSys(ms)`を使用します。分割対象IDでEEG欠測のあるセットはPhase 1で作成せず、問題のない残り5セットを保存します。

脳活動解析用EEGの信号行列は、ICA用チャンネル除外の有無にかかわらず元の32チャンネル順・32列を固定します。ICAから除外したチャンネルは、Eye成分除去を適用せず、フィルタ・トレンド除去済み信号をその列に保持します。`channel_names`は常に元の32チャンネル順とし、`ica_channel_excluded_mask`は同じ順序の32要素（ICA除外=`true`）として保存します。ICA除外チャンネル名と理由も付帯メタデータへ保存します。瞬き解析用データはFp1・Fp2・その平均の3列とし、同じICA除外maskと記録を付帯させます。

フィルタ・トレンド除去後の中間EEGは保存しません。No2のローカル保存は、最終的な上記2種類のセット別解析データと、再現に必要な小規模メタデータに限定します。

元EEGが2つの取得区間に分かれる場合、確認用波形成果物には`Part1`、`Part2`を付けます。最終解析データは取得区間別ではなくセット別に保存し、ファイル名は通常どおりIDとSet番号を使用します。由来となる`Part`と元入力ファイルは付帯メタデータへ保持します。

Phase 2解析1（No1）はローカルの加工済み・中間データを作成しません。QC要約、figure、ログ、Grand-averageは、次節の指定OneDriveだけへ保存します。試行別の `RT_TrialData.csv` は保存しません。

Phase 2解析1では、製品群を先に分け、各製品群の中で被験者別成果物とGrand-averageを分けます。`Individual/` 直下へ全被験者ペアのPNGだけを並べ、被験者別下位フォルダは作成しません。ファイル名は単独セッションIDではなく `ID<1回目>-<2回目>` とします。被験者別figureは、同一被験者の目薬あり条件とコントロールを同一図に示します。`GrandAverage/` には30試行幅版・50試行幅版のPNGだけを置き、平均線と平均±SEMの薄い帯を保存します。

同じNo1のセット別RT定量化は、各製品群の `SetMeanQuantification/` 直下へAllTrials版・Last80Trials版のPNGを各1枚置きます。下位フォルダは作成しません。前者は各SetのTrial 1〜320、後者はTrial 241〜320の算術平均です。補助CSVはNo1直下の `Sub/tables/`、実行要約JSONは `Sub/logs/` へ分離します。定量化だけの追加実行では、既存の `Individual/` と `GrandAverage/` を変更しません。

Grand-averageは全個人のEEG欠損セット処理と単純移動平均の完了後に作成し、個人別の移動平均値を同じセット・同じ進捗位置で被験者間平均します。個人figureは30試行幅、Grand-averageは30試行幅版と50試行幅版を作成します。200 ms未満のRTだけを除外し、200 ms以上の長いRTは保持します。生RTを先に被験者間でまとめてから平滑化しません。Grand-averageのシェードは標本SDではなくSEM（`SD/√N`）です。

Phase 2以降のfigure出力は、figure用フォルダにはPNGだけを保存します。Phase 2ではfigure以外を各No直下の `Sub/` へ分離します。No1の解析用表・QC CSVは `Sub/tables/`、実行要約JSONは `Sub/logs/` に分類します。No2の補助CSV・製品群別実行要約JSONは `Sub/` 直下へまとめます。

Phase 2解析2では、製品群ごとの `No2_Mistouch/CCube/` と `No2_Mistouch/VRohtoPremium/` のfigure用フォルダに、Set 1〜6の6パネル条件比較PNGだけを保存します。被験者別セット値CSV、製品群×Set集計CSV、製品群別実行要約JSON、感度分析の補助CSV/JSONは `No2_Mistouch/Sub/` 直下へまとめます。全体のバッチ要約 `No2_Mistouch_BatchSummary.json` はNo2直下に置きます。被験者識別子はNo1と同じ `ID<1回目>-<2回目>` とし、ローカルデスクトップへ中間データを保存しません。Figureの縦軸は `Mistouch (count)`、条件色はNo1より暗いControl `#402B5D`、C Cube `#963838`、Vロートプレミアム `#AC6820` に固定します。

`No1_BlinkRate/` 直下では製品群を先に分けます。検出確認成果物は条件比較単位ではなくセッションID単位とし、各製品群の `QualityCheck/BlinkDetection/` 直下へMAD方式のインタラクティブHTMLと、HTMLのReset表示と同じ縦軸スケールを使う横長PNGを一緒に保存します。全候補prominenceの0–500 µV・対数縦軸ヒストグラムPNGは `QualityCheck/ProminenceDistribution/` へ分けます。ファイル名は `Pair<1回目>-<2回目>_01_ID<1回目>_...`、`Pair<1回目>-<2回目>_02_ID<2回目>_...` とし、名前順が101、201、102、202のように被験者ペア内の実施順になるようにします。検出確認の青線は `Eye Blink Component Signal`、横長PNGの横軸は `Experimental Progress, %`、縦軸は `Amplitude (µV)` とします。HTML Resetと横長PNGの縦軸半幅は全使用Setの絶対振幅99.5パーセンタイル×1.60とします。時間変化の個人figureとセット別定量化は、Phase 2と同じく `ID<1回目>-<2回目>` の被験者ペア単位とし、各製品群の `Individual/` と `SetQuantification/` 直下へPNGを置きます。Grand-averageは各製品群の `GrandAverage/` へ保存し、各進捗位置の平均±SEM（標本SD÷√有効N）を表示します。被験者別サブフォルダを作らず、補助表とログはNo1直下の `Sub/` へ分離します。Blink Rate線・SEM帯の固定色はControl `#402B5D`、C Cube `#168C80`、Vロートプレミアム `#2A91B3`、セット別定量化は同じ条件対応の明度・彩度違いとしてControl `#66547D`、C Cube `#4CA79E`、Vロートプレミアム `#62AFC6`とします。個人Blink Rate図は最大線が上限の約70%、Grand-averageは `平均 + SEM` の最大値が上限の約75%となる5 blinks/min刻みの0始まりの縦軸を用い、右下のN・shade注記は表示しません。Set名、軸名、目盛、凡例はPhase 2と同等の大きさとし、セット別定量化の被験者ドットには固定seedの再現可能な左右ジッターを加えます。`Sub/tables/` には共通Setだけで算出したEye Drop／Control総検出数と大きい方÷小さい方の比率も被験者ペアごとに保存します。

Phase 2解析1のfigureはArial・英語表記とし、Set 1〜6を一つの横軸へ順番に連結します。横軸は `Experimental Progress, %` とし、Set 1を0〜100、Set 2を100〜200と連結し、Set 6の600まで50刻みの通常目盛りを表示します。縦軸は `Reaction Time (ms)`、下限は0 ms、目盛りは500 ms刻みとします。軸名は28 pt、x軸・y軸の目盛りは20 ptを標準とします。セット境界はグレー点線、セット名は図内上部へ表示します。条件色はControl `#563A7C`、C Cube `#C84A4A`、Vロートプレミアム `#E58A2B` に固定し、凡例は `Control` と製品群に応じた `Eye Drop (C Cube)` または `Eye Drop (V Rohto Premium)` とします。EEG欠損セットは個人figureで該当セッション側だけ線を欠損表示し、Grand-averageでは同じ被験者の両条件を同じセットで欠損化します。Grand-average凡例に変動帯のタイトルは付けません。Grand-averageの縦軸は、Cキューブ群・Vロートプレミアム群とも0〜1800 msに固定します。

成果物名には、追跡に必要な情報を次の順で含めます。

```text
Phase<番号>_No<番号>_<指標・内容>_<製品群>_<条件>[_ID<匿名ID>].<拡張子>
```

推奨トークン：

- 製品群：`CCube`、`VRohtoPremium`
- 条件：`EyeDrops`、`Control`、比較図では `EyeDropsVsControl`

例：

- `Phase2_No1_RTTrend_CCube_EyeDropsVsControl.png`
- `Phase2_No1_RTTrend_VRohtoPremium_EyeDropsVsControl.png`
- `Phase2_No2_Mistouch_CCube_EyeDropsVsControl.png`
- `Phase2_No2_Mistouch_VRohtoPremium_EyeDropsVsControl.png`
- `Phase1_No1_QC_IDxxx.png`

匿名IDは個別品質確認など必要な成果物にだけ付けます。氏名その他の個人情報はファイル名やメタデータへ含めません。

すべてのfigureには、横軸名、縦軸名、単位、色・線種の意味、凡例を図内へ記載します。単位が定義されない量は `[a.u.]` とします。複数チャンネルを上下表示するfigure・HTMLでは縦軸スケールを統一します。インタラクティブHTMLは、拡大・縮小、x軸移動、全体表示への復帰、表示チャンネル切替、カーソル位置の値確認を実際に操作してから成果物とします。

## スクリプトと成果物の対応

同じPhase番号とNo番号を、GitHubのスクリプト、ローカルの中間データ、OneDriveの成果物、Notionの記録で共通使用します。

| 解析 | 対象 | 対応 |
|---|---|---|
| No1 | Python | `Phase2_No1_ReactionTime.py` |
| No1 | ローカル中間データ | 保存しない |
| No1 | OneDrive成果物 | `Phase2_行動データ解析/No1_ReactionTime/` |
| No1 | Notion | フェーズ2ページに「No1 ReactionTime」として方針・結果・保存先を記録 |
| No2 | Python | `Phase2_No2_Mistouch.py` |
| No2 | ローカル中間データ | 保存しない |
| No2 | OneDrive成果物 | `Phase2_行動データ解析/No2_Mistouch/` |
| No2 | Notion | フェーズ2ページに「No2 Mistouch」として方針・結果・保存先を記録 |
| Phase 3 No1 | Python | `Phase3_No1_BlinkRate.py` |
| Phase 3 No1 | ローカル中間データ | 保存しない。Phase 1 HDF5を直接使用 |
| Phase 3 No1 | OneDrive成果物 | `Phase3_瞬き解析/No1_BlinkRate/` |
| Phase 3 No1 | Notion | フェーズ3ページに方針、ID・Set別検出結果、保存先を記録 |

スクリプトが新しいNoを取得した時点で、必要な出力フォルダを作ります。空のNoフォルダを先回りして大量に作りません。

## Notion

解析ストーリー配下の「フォルダ・ファイル管理」を本書と同期します。Phase 1〜5の各ページには、次を蓄積します。

- 解析目的と仮説
- 使用データと対象群
- スクリプト名・Phase番号・No番号
- 前処理または解析方法
- Cキューブ群の目薬あり対コントロール
- Vロートプレミアム群の目薬あり対コントロール
- 観察結果
- 解釈
- OneDrive成果物の保存先
- 問題と未確定事項
- 次に行うこと
