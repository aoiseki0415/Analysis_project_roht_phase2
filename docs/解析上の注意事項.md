# 解析上の注意事項

## 目的

解析対象の選定と例外処理を実装へ確実に反映するための必読文書です。解析スクリプトの作成・実行、対象抽出、集計の前に、README、運用ルール、本書、Notionの `解析ストーリー` 配下を毎回確認します。Notionの「被験者・セッションID対応表」と「解析の際に注意すべき点」がライブの正本です。

## 現在の解析対象

- 実験データ総計および解析使用予定：40名
- 解析対象外：ID 130／230の被験者のみ。この被験者は総計40名に最初から含めません。
- ID 115／215：解析に使用します。
- ID 125／225：解析に使用します。ID 225の分割EEGを統合してから使用します。
- 生データは削除せず、解析コード側で採否と例外処理を管理します。

## EEG解析はJSONに依存しない

- 必須入力は、EEG CSV、行動データのイベント・ブロック結果、OSシステム時刻です。
- EEG JSONは必須入力にしません。存在する場合も、電極マッピングや記録情報の補助確認に限ります。
- JSON欠損だけを理由に、セッションや被験者を除外しません。
- Phase 3の瞬き主解析列 `Fp1_Fp2_mean` は使用可能なFpチャンネルの平均です。通常はFp1・Fp2平均ですが、ID124・209ではPhase 1のICA学習からFp2が除外されて補助Fp2列が全SetでNaNのため、主解析列はFp1のみから構成されます。主解析列が有限であることを確認した上で、両IDも他IDと同じPhase 3処理へ含めます。
- ID 115はJSONがありませんが、EEG CSVと行動時刻を検証して解析に使用します。対応するID 215も使用します。
- 解析前に、EEG CSVのチャンネル名・数、Timestamp、256 Hzのサンプリング情報、記録範囲、全体の読み込み可否、行動時刻との重なりを確認します。

## 分割EEGの統合

分割対象は **ID 109、120、135、225** です。ID 119ではありません。実ファイル上、ID 109には2記録、ID 119には1記録があります。

各対象IDでは次を守ります。

1. 2つのEEG CSVを時刻順に読み込みます。
2. 元ファイル名、各区間の開始・終了時刻、区間境界を保持します。
3. 2区間を一つの論理的なEEGセッションとして統合してから解析します。
4. 記録間の空白は欠測として保持し、信号値を補間して連続記録のように扱いません。
5. 前回MATLABと同じく、EEGの `OriginalTimestamp × 1000` と行動側の `*Sys(ms)` で同期します。

実データを確認した結果、分割はすべて単純なブロック間分割ではありません。

- ID 109：ブロック1の途中に記録間の空白があります。
- ID 120：ブロック6の開始後に記録間の空白があります。
- ID 135：ブロック2の途中で前半記録が終了し、後半記録はブロック3前から再開します。
- ID 225：ブロック4の途中に記録間の空白があります。

Phase 1では、ID 109のセット1、ID 120のセット6、ID 135のセット2、ID 225のセット4を前処理対象から除外し、各IDの問題のない残り5セットを使用します。該当セットではEEG欠測中に実施された行動試行があり、欠測前後の単純結合は行いません。

## その他の既知の例外

- ID 109：行動課題の再開始記録があります。完了した行動記録を主対象としてEEGと同期します。
- ID 134：行動記録が再開始されています。最初の空記録を除き、完了した2回目の行動記録を使用します。
- ID 229：ファイル名に `-2` 接尾辞があります。ID 229として対応付け、元ファイル名を保持します。

## Phase 2行動RT解析における分割・再開始記録

- ID 109、120、135、225は、EEG分割を理由に被験者ペア全体を行動RT解析から除外しません。
- 候補となる行動results CSVを確認し、各セットで重複のない320刺激試行を確定します。再開始等で同じTrialが複数存在する場合は二重計上せず、完了記録を優先します。必要な場合だけ元ファイルとTrial番号を保持して分割片を再構成し、欠損試行の補間・推定は行いません。
- Phase 1でEEG欠損のため除外したセットに合わせ、個人解析では **ID 109のSet 1、ID 120のSet 6、ID 135のSet 2、ID 225のSet 4** の行動RTを全320試行NaNにします。対応するもう一方のセッションは個人figureでは通常どおり描画します。
- 上記のEEG欠損セットを先にNaN化し、その後200 ms未満のRTだけを予期反応として除外します。200 ms以上には上限除外を設けず、長いRTも注意の逸脱（lapse）を反映しうる情報として保持します。平滑化は各Set内の30試行等重み単純移動平均とし、Grand-averageだけ50試行幅版も追加します。
- Grand-averageでは被験者内対応を保つため、上記4ペアについて、EEG欠損セットと同じセットを **両条件とも** NaNにしてから製品群別に集計します。これにより該当セットの有効人数Nは両条件で同じになります。
- No1のセット別RT定量化もGrand-averageと同じ被験者内対応を使用します。上記4ペアの該当セットは両条件とも定量値をNaNとし、ドット、接続線、条件平均から除外します。定量値は移動平均後の値ではなく、200 ms未満を除外した試行別RTから、各Setの `AllTrials`（Trial 1〜320）と `Last80Trials`（Trial 241〜320）の2種類の算術平均を作成します。
- Set別の推測統計でも、各Setで両条件が有限の被験者だけを両側対応ありt検定へ含め、欠測を補完しません。現行の主PNGは未補正p値を表示します。統計CSVには未補正値に加えてBonferroni・Holm・Benjamini–Hochberg FDR補正値を併記します。補正法の扱いは今後変更し得るため、図とCSVの役割を混同しません。
- Phase 2実行前に、Google Driveの匿名共有タブから、2セッションID、製品群、目薬ありの実施回を確認します。IDの100番台／200番台だけで目薬条件を決めません。
- 全被験者へ同じNo1 Pythonコードをループ適用し、被験者ごとのコード変更や手作業の代替処理を行いません。

## 解析開始前チェック

- Notionの対応表で、セッションID、製品、「目薬使用回」（1回目／2回目）を確認したか
- 現在の解析使用可否と除外対象を確認したか
- 分割対象が109、120、135、225であることを実装へ反映したか
- JSONを必須入力にしていないか
- 分割区間の空白を補間していないか
- 分割対象の影響セットをPhase 1から除外し、残り5セットだけを使用しているか
- Phase 2では分割・再開始行動記録の重複を二重計上せず、各セットの320刺激試行を実データから確定したか
- Phase 2個人解析で、ID 109 Set 1、ID 120 Set 6、ID 135 Set 2、ID 225 Set 4を先にNaN化し、それ以外のRTを長さで除外していないか
- Grand-averageで、上記4ペアの同じセットを対応するもう一方の条件も含めて両条件ともNaN化し、有効人数Nを一致させたか
- セット別RT定量化で、移動平均値ではなく200 ms未満を除外した試行別RTを使い、`AllTrials`（Trial 1〜320）と `Last80Trials`（Trial 241〜320）の両方を作成し、EEG欠損セットを両条件ともNaN化したか
- Set別統計で両条件が揃う被験者だけを使用したか。主PNGは未補正p値、CSVは未補正・Bonferroni・Holm・FDRの4列になっているか。全Set統合は1検定であることを明記したか
- Phase 2の製品群・条件・2セッション対応をGoogle Driveの匿名共有タブで確認したか
- Phase 2 No1がローカルデスクトップへ加工済み・中間データを書き込まないことを確認したか
- Phase 3 No1でprominence閾値を `中央値 + 12 × 1.4826 × MAD` とし、被験者ごとに係数を変えていないか
- Phase 3の目視QCで、各セッション最大3分の範囲内にx軸を個々のスパイク形状が判別できる幅まで拡大し、連続する表示窓を送って使用可能な全時間帯を確認し、終了後にHTMLを閉じたか
- Phase 3のNotion結果で、Eye Drop／Control双方の共通Setにおける総検出数と大きい方÷小さい方の比を記録し、2倍以上または片方が0なら `要確認` としたか。このQCだけを理由に除外や個別閾値変更をしていないか
- Phase 4 No1で、全32chのPSDを1秒Hann窓・1秒移動・256点FFT・1 Hz分解能で計算し、4–7 Hzを平均しているか
- Phase 4 No1で、保存済みPSDが存在するときにfigure調整だけを理由としてPSDを再計算していないか
- Phase 4 No1の個人時間変化で欠測側だけを非表示とし、Grand-average・定量化・topographyでは既知4ペアの対応条件側も同じSetから除外したか
- Phase 4 No1で、ローカルcacheは未平滑PSDを保持し、個人時間変化とGrand-averageだけにSet内60秒中心化単純移動平均を適用し、定量化とtopographyは未平滑PSDから計算しているか
- Phase 4 No1で、MNE 1.13の実在する `psd_array_welch` 引数だけを用い、1秒窓をNumPyで1秒ずつ移動しているか。関数内部の `n_overlap=0` と外側窓の移動を混同していないか
- Phase 4 No1で、Set端を前後128 samplesの反射paddingとして処理し、窓中心時刻とprogressを元のSet時刻から保存したか
- Phase 4 No1で、Phase 1区間mask適用後の有限かつ正の未平滑PSDを、セッションID・ch別に全利用可能Setでプールし、`log10(PSD)`の平均＋3標準偏差（`ddof=1`）を超える上側値だけをNaNにしたか。Set別閾値、対応セッション混合、下側除外をしていないか
- Phase 4 No1で、元PSDを上書きせず、log閾値、線形閾値、除外mask、Set・ch別除外数・率を保存し、個人・Grand-averageはmask後に60秒平滑化、定量化・topographyはmask後の未平滑PSDを使用したか
- Phase 4 No1のfigureについて、寸法、Arial、軸名、単位、目盛、線幅、色、y上限、統計位置、topographyスケールを `docs/Phase4_脳波解析仕様.md` の固定値から変更していないか
- Phase 4 No1_addをNo1本体と別スクリプト、別cache、別OneDriveルートで扱い、No1のシータmaskを流用していないか
- Phase 4 No1_addで、Fzの1–30 Hz線形PSDを1 Hz刻みで保持し、1–30 Hz平均からセッションID別・全Set一括のbroadband log10上側3SD時間maskを作り、該当時間の全周波数binをNaNにしたか
- Phase 4 No1_addで、mask後に各周波数binをSet内60秒平滑化し、その後に各Set100 progress点へ変換してから被験者間平均したか。Eye Drop、Control、`Difference in PSD = Eye Drop − Control` の3段Grand-averageだけを出力したか
- Phase 4 No1 topographyとNo1_add差分mapのcolorbarを `Difference in PSD (µV²/Hz)` とし、条件差の表記に `Δ` を使用していないか
- Phase 4 No1_addの上2段を `viridis` の `0–30 µV²/Hz`、下段をゼロ中心 `RdBu_r` の `−20–20 µV²/Hz` に固定して2製品で共通化し、表示範囲外の保存数値をクリップせず、補間やshadeを追加していないか
- Phase 4 No1_subで、No1の検証済みcacheを読み、セッションID・ch別にSet 1有限値平均を計算してから、平滑化前のPSDを変化率へ変換したか
- No1_subのFz時間変化だけを変換後にSet内60秒平滑化し、定量化とtopographyには未平滑変化率を用いたか。Set 1単独をt検定せず、全Set統合版にはSet 1–6の全有限時間窓を含めたか
- No1_subでSet 1欠測のペア109–209を両条件とも除外し、その他の既知欠測Setは集団解析で対応条件側も同じSetから除外したか
- EEG同期に `OriginalTimestamp × 1000`、行動同期に `*Sys(ms)` を使用しているか
- 5秒以上の連続0等、確定版の自動除外条件に該当したチャンネルを、利用者承認を待たずICA学習・ICA適用対象からだけ除外し、理由を記録しているか
- 脳活動解析用EEGを元の32チャンネル順・32列で保存し、ICA除外チャンネルもフィルタ・トレンド除去済み信号のまま保持しているか。32要素のICA除外mask・チャンネル名・理由を脳活動・瞬き解析用データの両方へ保存しているか
- ICA学習用の不良区間は除外し、補正波形で置き換えていないか
- ICLabel `eye blink` 確率0.80以上の成分だけを除去し、`ICA.find_bads_eog()`や独自複合条件を除去判定に追加していないか
- topomapのFp1・Fp2空間バランスは事後QCに限定し、IC除去基準に追加していないか
- 出力先を指定OneDriveフォルダへ限定したか
- 今回の実行直前に、README・運用ルール・本書・Phase 1仕様書・Notion解析ストーリーを読み直したか
- 全IDを同じ確定版Pythonスクリプトの実行で処理し、IDごとの探索的処理や手作業の代替を加えていないか
- 実行後にOneDrive・ローカル保存・HDF5読み戻し・QC・NotionのID別2表・解析記録まで完了したか
- Computer Useで開いたHTMLやfigureを確認後に閉じたか
