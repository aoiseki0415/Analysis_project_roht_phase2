# Phase 4 No11・No11_sub：意思決定と対応履歴

更新日：2026-11-14。**本書は経緯・過程の記録。最新の実行方法・図・保存規則は[現行解析仕様](../Phase4_No11_解析仕様.md)を正本とする。** No11自身の実行結果は同仕様の結果節とOneDriveのSubに分離する。

## 1. 目的が確定するまで

利用者は、Fzのlow-alphaを扱うNo10／No10_subと同じ解析をPzでも行うことを指定した。新規解析番号をNo11／No11_subとし、帯域は現行No10と同じ8–10 Hz、条件比較・欠測・統計・Figure比率を継承する方針が確定した。

No10では主要解析の後に指定ペア除外やtopography限定の除外版を追加してきたが、No11ではまず**追加の被験者選別なしの主要解析だけ**を行い、個人結果確認後に必要なら別途判断する。全頭topographyは代表ch変更で変わらないため、No11では重複出力しない。

## 2. 確定した設計判断

| 判断 | 理由・境界 |
|---|---|
| No11=Pz絶対PSD、sub=各条件自身のSet 1変化率 | Fz版と同じ定義でPzを確認するため |
| 帯域8・9・10 Hz、追加PSD計算なし | 現行No10に全32chの同一帯域・同一窓PSDが保存済み |
| source hashはNo10生成設定で検証、Pzは解析時選択 | 代表chを変えるだけで同一数値cacheを再生成・書換しないため |
| ローカル派生cacheなし | 重複データと版混在を避け、既存検証済みcacheを正本に保つため |
| No10の事後除外集合を適用しない | Fzでの事後判断を未確認のPzへ拡張しないため |
| topography・TFMなし | 前者はNo10と重複、後者は今回の依頼範囲外 |
| No11とsubは同じブルーグレー系 | 既存のNo10オリーブ等と区別しつつ、同じ解析の絶対値／変化率を対応づけるため |
| 旧IAF No11と分離 | 廃止済みFz前後半IAFの手法・採否・配色を誤用しないため |

確定色はCキューブ線`#476975`・定量化`#7B949D`、Vロートプレミアム線`#789BA3`・定量化`#A0B8BD`。Controlは共通の線`#402B5D`・定量化`#66547D`。色選択は表示の識別性に関する決定で、数値計算には影響しない。

## 3. 今回の開始指示と作業順序

2026-11-13の明示的な開始依頼に基づき、運用文書と現行No10仕様を再確認し、方針・保存先の記録、No11用フォルダ、実装、pilot、全対象実行、独立検証、文書・Notion更新、Git commit／push／remote確認の順で対応する。

実行前の予定と実行済み実績を混同しない。準備時点では方法・Figure・保存構造だけを現行仕様に記載し、実数N・検証・結果は後から別節へ追記する。個人ID付き結果・ログは許可済みOneDrive Subに置き、Gitへ転記しない。

No10_subの空間的な外れ値判定に関する直前の相談は、今回のNo11開始指示とは別件である。合意前のシミュレーション案をNo10やNo11へ実装せず、既存No10の結果・コード・規則を今回の作業で変更しない。

## 4. 実行後の検証・記録

2026-11-13に、同一entrypointで少人数試行後、絶対PSD40ペア・変化率39ペアを実行。171 PNG・17表の独立照合、元80 cacheの不変、全12群図・代表個人8図の目視を確認した。実数N・統計と表示上の限界は現行仕様の第11節へ分離した。

完了判定は数値処理と切り分けて強化し、実行時の数値コードhash、独立監査記録、全PNG hash、CSVの再構成照合、JUnit、文書・Notion、Git remote SHAを要求する。実行後の強化は管理スクリプトの完了ゲートだけで、数値engine・validator・出力は変更していない。実行時と納品時の管理スクリプトhashを区別して記録する。

OneDriveへの最初の書込はsandbox制約で拒否されたため、許可された指定フォルダへの再試行で実行した。別の保存先への代替や既存入力の変更はしていない。単なるローカル保存をサーバー同期確認とは扱わない。

Vプレsub群図は、No10と同じ平均線基準の対称軸を維持したためSEM帯上端の一部が範囲外となった。図の数値を切り詰めたり、その場の判断で軸・対象を変更したりせず、結果節と視覚QAへ明記した。

実行コマンド、時刻、版、入力識別、検証成否、失敗からの修正は各Noの`Sub/logs/`を正本とし、ここへ日次作業ログや参加者別結果を重複保存しない。最終commit／push／remote照合の証跡は`No11_DeliveryVerification.json`で確認する。

## 5. 指定ペア除外追加版の確定（2026-11-14）

初回の「まず全員で行い、個人確認後に追加を検討する」方針に続き、利用者がNo11とNo11_subの両方へ同じ4ペアの除外版を明示指定した。**主結果は維持し、Grand-average・Set別／全Set統合定量化だけを追加**する。初回の「指定除外版は作らない」は初回実行範囲の説明であり、現在の追加版を禁止する規定ではない。

対象の正本は[解析上の注意事項](../解析上の注意事項.md)。入力表記に省略されたIDが1件あったため、NotionとGoogle匿名共有シートの一意な対応を照合して正規化した。対応確認と原記載は同注意事項・OneDriveの監査記録に置く。

今回の指定は事後・探索的な感度分析であり、ノイズを確定する自動手法として説明しない。No10の指定除外集合やtopography選別を継承せず、No11専用集合だけを適用する。元PSD・各IDのbaselineやmaskは変更せず、残存ペアで群統計と表示軸を再計算する。

新しい追加版専用入口・監査を実装し、全員版のファイルhashを保護して実行する。方法・図・保存構造は現行仕様第5.4節等、実数N・統計・完了検証は同書の実行結果節へ分離して記録する。

同日に12 PNGを追加し、80元cache・既存主要ファイルの不変、18 CSVの独立照合、全追加図の目視、391テストを確認した。最初のOneDrive書込はsandbox制約で拒否されたが、同一の許可済み保存先へ再試行し、別フォルダへ代替していない。計算engine・除外集合を結果に合わせて変更する試行錯誤は行っていない。完了証跡は追加版専用Delivery JSONとGit履歴で管理し、初回の実績を上書きしない。
