# Phase 4 No10_sub・No11_sub：被験者除外の再検討履歴

記録日：2026-11-16。**過程・旧条件・旧実績専用。現行の採否は[注意事項](../解析上の注意事項.md#phase-4-sub被験者除外の現行指定2026-11-16)、方法は[共通方針](../Phase4_除外あり追加解析の共通方針.md)と各No仕様を正本とする。** 対象IDを本書へ重複転記しない。

## 1. 議論と今回の決定

1. 代表chのGrand-average・定量化の被験者除外と、topographyのペア×ch×Set除外は異なる集合となることを整理した。
2. 他者と異なる現象・大きなPSD Change・群平均への寄与だけでは除外を優先せず、絶対PSDやbaselineも含む信号品質を重視する方針を確定した。
3. No10_subの旧指定は持続的に大きな変化率が契機であり、信号品質の問題を実証したものではなかった。利用者は絶対PSDも見た上で、Vプレ2ペア・Cキューブ1ペアとも除外根拠が不十分と判断した。
4. **No10_subは被験者除外を検討した上で、両製品とも追加除外版を作らないと決定。** 未検討・保留・除外方針の欠落ではない。既存の全baseline適格主結果を採用する。
5. No11_subも同じスタンスで検討し、Vプレ1ペア・Cキューブ3ペアの既存除外を維持すると再確認。新たな個別原因を診断したとは記録しない。
6. No11絶対PSD、topography v3、No1–3・他解析は変更しない。No10_subの復帰をPzや全頭へ自動反映しない。

## 2. 旧No10_sub指定版の方法（現在は廃止）

- 旧8–11 Hz版の大きな変化率を契機に、Vプレ2ペア・Cキューブ1ペアを指定。帯域変更後の8–10 Hzでも同じ指定を適用した。
- `SpecifiedPairsExcluded`は指定ペアの両条件・全Setを外し、FzのGrand-average、Set別・全Set統合定量化だけを追加した。元cache・個人・全員主結果・topographyは保持した。
- 平滑化後の群mean/SEM、未平滑定量値、両側対応ありt検定・3補正、除外後のy軸を既存方式で再計算した。Set 1は検定せず、AllSetsには含めた。
- 全対象のsub `--all`／`--group-outputs-only`後に自動生成し、`--sensitivity-only`でも再生成できた。**この生成経路は現行で停止する。** 旧指定・旧コマンドを現在の方法として復活させない。

## 4. 現行成果物との切り分け

- 旧追加6 PNGは現行閲覧先から撤去し、PNGを履歴へ複製しない。旧9 CSV・1 JSONは元相対パスとSHA-256を保持してSub/historyへ移す。

- No11_subは対象・手法・図が不変のため再生成せず、再検討して維持した意思決定と保護確認を記録する。No11絶対PSDは今回の判断対象外。

## 5. 帯域置換時の手順（2026-11-12の履歴）

- 当時の専用ラッパー`run_phase4_no10_band_revision.py`が40ペアmanifestで本番main／sub入口を呼んだ。匿名対応表を照合しmanifest SHAを固定、全80入力preflight後に進めた。
- 旧CSV・JSON・LOGを各Sub/history/Before8to10Hz_20261112へhash付き保存。旧PNGは新帯域図に置換し、現在表示へ混在させなかった。
- 当時のmain `--all --force-recompute`→sub `--all`→独立監査で80 cache・260 PNGを再生成した。現行では旧指定版が廃止されたため、この260 PNG前提の手順を通常実行へ使用しない。
- 保存PSD・mask・baseline・定量・統計・群値・topographyを独立照合し、1,428窓×32chを元EEGのSciPy Welch抜粋で確認した。全窓の元EEG再計算ではない。
- 実行commit・時刻・終了コード・hash・警告・失敗をSub/logsへ保存。数値照合と実画像確認、ローカル保存とクラウド同期を区別した。
- 当時の`--complete-verification --review-manifest`はGitのHEAD／remote、manifest・画像hashと保護対象を照合し、DeliveryVerification_20261112_8to10Hz.jsonへ保存した。今回の撤去実績の代用にはしない。

## 6. 今回の実装・実行過程

方法文書を先行更新し、No10_subから旧指定版の自動生成を撤去した。廃止CLIは理由付きエラーで停止させ、No11等が使う共通処理とは分離する。退役runnerは具体的16ファイルをplanで検証し、実行前後の保護SHAを照合する形とした。

最初の指定OneDriveへの書込はsandbox制約で記録保存時に停止し、既存成果物は変更されなかった。同一の許可済み場所へ再試行し、11:50:17–11:50:19 JSTに旧6 PNG撤去・非PNG10件移管を完了した。別の結果保存先へ切り替えたり、手法・採否を結果に合わせて変更したりしていない。

主結果は旧指定対象を既に含むことを読み戻し確認したため、同じ計算・図を再生成しなかった。No11_subは利用者が再検討して維持した判断を記録し、既存の対象・結果を保護した。現行の確認結果はNo10仕様第13節・No11仕様第11.5節、実行・移管・hashはOneDrive Sub/logsの退役JSONへ分離する。全464テスト成功・Ruffの結果はNo10仕様第13節のGit管理記録であり、全stdoutをOneDriveへ保存したという意味ではない。初回の書込制約と復旧は本節に記録した。
