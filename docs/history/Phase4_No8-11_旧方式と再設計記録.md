## 出発点と最終判断

旧方式はPz/FzのSet別IAFと60秒区間・5秒移動IAFを計算した。背景補正・周波数平滑化・ピークz値・最低有効時間の判定によりNaNが多く、ユーザーが求める「まず元のPSD上の局所ピークとSet間推移を見る」探索と一致しなかった。旧計算の完了と、今回採用する手法を区別する必要が生じた。

| 論点 | 最終判断と理由 |
|---|---|
| 推定対象 | PzはNo8＝全Set、No9＝前後半。FzはNo10＝全Set、No11＝前後半。60秒の連続推移は廃止 |
| ピーク | 線形平均PSDの8–15 Hz局所最大のうち最高峰。帯域内argmaxではない |
| 採否 | z・背景補正・SG・顕著さ・最低coverageの追加足切りを廃止。Phase 1不良窓除外は保持 |
| 入力時間 | Set全体／前後半全体を対象に、10秒・50% overlap窓を平均。窓別IAF平均ではない |
| Figure | Eye Drop PSD、Control PSD、両条件IAFの3パネル。6本・12本の合成デザインを確認・承認 |
| 保存 | 旧結果と合成プレビューを現行結果から削除。旧IAF cacheも削除し、新schemaで再計算 |
| コード | 旧実装・テストは履歴層へ退避。新方式は別の計算契約で作るが、今回は実装しない |

旧品質基準を科学的に無価値と判断したのではない。今回は顕著さの厳密な選別より、局所ピークと元PSDの可視化を優先した。微小峰を拾うリスクは現行仕様へ明記する。

## IAF差分Grand-averageと明瞭性評価の計画（2026-11-10）

個人図の確認後、各人が元来示しやすいピーク周波数の違いを考慮しつつ、Set進行に伴う変化の集団傾向を見たいという追加目的が定まった。条件間差を先に一つの系列へまとめる複雑な方法ではなく、各条件自身の基準区間からの差（Hz）を個人ごとに作り、それを条件別に被験者平均する方針とした。

| 決定 | 理由・境界 |
|---|---|
| 保存済みIAFから差分を作る | PSD・ピークを再推定せず、既存の個人値との対応を保つ |
| No8/10はSet 1、No9/11は1aを基準 | 全Set／前後半の解析単位を保ち、後者の基準をSet 1平均へ置換しない |
| まず全利用可能データ版 | 後続区間の欠測だけでは被験者全体を除外せず、その区間の条件対応を保つ |
| 基準が片条件欠測なら当該Noの差分群集計でペア除外 | 個人基準の差が定義できないため。既存個人図や他Noの採否とは別 |
| 明瞭なピークを持つ対象に絞った追加版も検討 | 局所最大が機械的に算出できても、代表的alpha峰とは限らないため |
| 全区間で明瞭なことは要求しない | 明瞭から不明瞭になる変化も情報として保持する。どこかに明瞭な区間があれば全区間不明瞭とは扱わない |
| No・製品・条件ごとに独立評価 | Pz/Fz、全Set/前後半、Eye Drop/Controlで所見が変わり得るため |
| 片条件のみ明瞭は別区分・最終採用未決 | 両条件でどこかに明瞭なペアと混同せず、評価結果を見て決める |
| 評価は既存計算への足切りではない | z・prominence等の自動除外を復活させず、保存IAFや不明瞭区間を変更しない |

今回依頼の実行範囲は、方針・評価手順の文書化とCodexによるピーク明瞭性評価、CSV/Markdown共有および記録まで。Grand-averageは未実装・未実行で、対象限定版の最終採用集合も未確定。個人別評価はOneDrive、最新の手法・集計要約はGitHub共有仕様とNotion、議論の理由は本履歴という層に分ける。評価結果を確定した解析除外と読み替えない。

| 決定事項 | 理由・境界 |
