# Phase 3 No1：瞬き検出・Blink Rate解析 共有用仕様書

> **確定版（2026年10月3日）**：本書には、現行スクリプトで再現される最終決定事項だけを記載する。

## 1. 解析の目的

ガボール課題中の瞬き頻度が実験の進行に伴ってどのように変化するかを可視化・定量化し、目薬あり条件と目薬なし条件（Control）を比較する。

被験者は使用した目薬に基づいて次の2群に分ける。2製品群は混合せず、各群内で同一被験者の2条件を対応付けて比較する。

- Cキューブ群：Eye Drop vs Control
- Vロートプレミアム群：Eye Drop vs Control

## 2. 解析の概要

Phase 1で作成したセット別瞬き解析用HDF5を入力とし、ICAで抽出された瞬き関連成分のセンサー空間信号から瞬きイベントを検出する。

No1では、次の結果を作成する。

1. 瞬き検出のQuality Check：検出信号とピーク位置をセッション全体で確認する。
2. 被験者別Blink Rate推移：6セットを連結し、実験進行に伴う瞬き頻度の変化を表示する。
3. 製品群別Grand-average：被験者別Blink Rateを同じセット・同じ進捗位置で被験者間平均する。
4. セット別定量化：各セットの検出総数をセット実時間で補正し、Eye DropとControlを被験者内で比較する。

## 3. 解析の流れと確定設定

### 3.1 被験者・条件の対応付け

- 1回目ID、2回目ID、目薬ありID、使用製品を匿名化された被験者対応表から確定する。
- IDの番号帯から条件を推測しない。
- 全被験者を同一のPythonスクリプトと固定パラメータで処理し、被験者ごとに閾値やコードを変更しない。

**理由：** 同一被験者の2条件を正しく対応させ、製品群・条件の割付誤りと解析手順のばらつきを防ぐため。

### 3.2 入力とEye Blink Component Signal

入力は、Phase 1で保存したセット別 `IDxxx_SetN_blink_signal.h5` とする。主解析信号は **Eye Blink Component Signal** と呼ぶ。

作成手順は次のとおりである。

1. Phase 1で連続EEGをICAにより独立成分へ分解する。
2. ICLabelの `eye blink` 確率が0.80以上の成分だけを瞬き関連ICとして選ぶ。
3. 選択したICのチャンネル別寄与をICAの混合行列でセンサー空間へ戻す。この信号は、計算上「ICA適用前EEG − 瞬き関連IC除去後EEG」と同値である。
4. 使用可能なFp1・Fp2を時点ごとに算術平均する。ICA学習から片方が除外された場合は、残るFpチャンネルの信号を主解析列とする。
5. Phase 3でセットごとに1–10 Hzのゼロ位相バンドパスフィルタを適用する。

Fp1・Fp2単独信号は検出数の補助QCにだけ使用し、主解析や条件比較には用いない。

**理由：** Phase 1で瞬き関連と判定・除去した成分そのものの寄与を用いることで、脳活動成分を主対象とせず、瞬きに由来する時間変化を解析するため。

### 3.3 瞬きイベントの検出

ピーク検出には `scipy.signal.find_peaks` を使用する。

| 項目 | 確定設定 |
|---|---|
| 検出前フィルタ | 1–10 Hz、ゼロ位相、セット内で独立に適用 |
| Peak height | 設定しない |
| Prominence閾値 | `median(P) + 12 × 1.4826 × MAD(P)` |
| 閾値の母集団 | 同一セッションの使用可能な全セットに含まれる局所ピーク候補のprominence `P` |
| MAD | `median(|P - median(P)|)` |
| Minimum peak distance | 100 ms |
| Peak width | 20–320 ms |

係数12は文献推奨値ではない。4被験者ペアで係数8・10・12を探索比較し、係数10による初回全対象出力で過剰検出が確認されたため、過剰検出を抑える値として12を全ID共通で採用した。

パーセンタイル閾値は使用しない。IDごとの上位一定割合を選ぶと、実際の瞬き頻度や振幅分布が異なっていても、抽出割合と総数がID間で似通いやすくなり、被験者差・条件差を弱める可能性があるためである。

### 3.4 瞬き検出のQuality Check

セッションIDごとに、次を保存する。

- 瞬き抽出確認HTML
- HTMLのReset表示と同じ縦軸スケールを使った横長PNG
- 候補prominence分布と検出閾値を示すPNG

検出確認図では、青線を `Eye Blink Component Signal`、中抜き丸を検出瞬きとする。横軸は6セットを0〜600へ連結した `Experimental Progress, %`、縦軸は `Amplitude (µV)` とする。HTMLはx・y方向の拡大縮小、ドラッグ、左右キー移動、Reset、カーソル値確認に対応する。

HTML Resetと横長PNGの縦軸半幅は、全使用セットの絶対振幅99.5パーセンタイル×1.60とする。prominence分布は横軸0–500 µV、縦軸対数とし、閾値と500 µV超の候補数を示す。

目視QCは各セッション最大3分とする。x軸を個々のスパイク形状が確認できる幅まで拡大し、先頭から末尾まで連続する表示窓を送って、全使用時間を少なくとも1回確認する。波形と検出丸印の整合性を「良好／概ね良好／要確認」で記録し、確認後はHTMLを閉じる。

**理由：** 自動検出数だけでは過剰検出・見逃しを評価できないため、全使用時間について信号形状と検出位置を目視確認するため。

### 3.5 Blink Rateの時間変化

Blink Rateは各セット内で独立に計算する。

1. 中心時刻の前後30秒を含む60秒窓を1秒刻みで移動する。
2. 窓内の検出瞬き数を、実際の窓長（分）で割り `Blink Rate (blinks/min)` を求める。
3. セット端では利用可能な時間だけを使い、短くなった実窓長で分母を補正する。
4. 得られた1秒刻みBlink Rateへ、同一セット内だけで15秒の中心化単純移動平均を適用する。
5. 平滑化後、各セットの実時間を0〜100%へ線形変換し、6セットを0〜600の進捗軸へ連結する。

セット境界を越えて窓や平滑化を適用せず、セット端を削除しない。

**理由：** 60秒単位の瞬き頻度を維持しつつ、セット時間の個人差を進捗軸上で揃え、セット内の時間変化を比較するため。

### 3.6 被験者別Blink Rate figure

- 同一被験者のEye DropとControlを同一figureへ表示する。
- 横軸：`Experimental Progress, %`、0〜600
- 縦軸：`Blink Rate (blinks/min)`、下限0
- セット境界：グレーの縦点線
- セット名：`Set 1`〜`Set 6`
- 縦軸上限：2条件の線の最大値が約70%位置となる値を5 blinks/min単位で切り上げる。
- フォント：Arial、英語表記

### 3.7 Grand-average

被験者別Blink Rateの作成後、製品群ごとにEye DropとControlを被験者間集計する。

- 各セット内の15秒平滑化Blink Rateを、セット境界を越えずに0〜100%の100点固定グリッドへ線形補間する。
- 各進捗位置で被験者間平均を求める。
- シェードは平均±SEMとする。
- SEMは、その位置の標本SD（`ddof=1`）を有効人数Nの平方根で割る。
- 欠測セットを補間せず、その位置の有限値だけで平均・SD・SEM・Nを求める。
- 縦軸は0始まりとし、`平均 + SEM` の最大値が約75%位置となる値を5 blinks/min単位で切り上げる。
- 右下のN・shade説明は表示しない。
- 標準版は保持し、Cキューブ主要版、Vロートプレミアム主要版、VロートプレミアムのPair 133–233 Set 1〜3除外版について、共通の10〜30 blinks/min・5 blinks/min刻み・薄いグレーの横グリッドを用いた拡大表示版も追加する。拡大版の中心的な平均線は縦方向の約45〜50%に位置し、平均±SEM帯も表示範囲内に収める。

**理由：** 被験者を同じ重みで集計し、条件ごとの平均推移と平均推定の不確実性を示すため。

### 3.8 セット別定量化

各被験者・各条件・各セットについて、次式で定量値を求める。

```text
Set Blink Rate [blinks/min]
= セット内の検出瞬き総数 ÷ セット実時間 [min]
```

移動窓Blink Rateの時間平均は使用しない。

- 製品群ごとにSet 1〜6の6パネルを横一列に配置する。
- 左をEye Drop、右をControlとする。
- バー：条件内の被験者間平均
- ドット：各被験者のセット定量値
- 接続線：同一被験者の2条件の対応
- ドット：固定seedによる再現可能な左右ジッター
- 縦軸：6パネル共通の `Blink Rate (blinks/min)`
- 推測統計と有意差記号：表示しない

**理由：** セット時間の差を補正し、被験者を解析単位として条件平均と被験者内対応を同時に示すため。

### 3.9 欠測セット

Phase 1でEEG欠測と確定した次のセットは補完しない。

- ID109 Set 1
- ID120 Set 6
- ID135 Set 2
- ID225 Set 4

Grand-averageとセット別定量化では、被験者内対応を維持するため、対応するもう一方の条件も同じセットから外す。

### 3.10 Vロートプレミアム群の追加集計

主要結果は、従来どおり全使用可能データで作成し保持する。

追加解析では、ID233 ControlのSet 1〜3で瞬き成分が十分に抽出されていないという事後確認に基づき、Pair 133–233のSet 1〜3をEye Drop・Controlの両条件とも群集計から外す。追加対象はGrand-averageとセット別定量化だけとし、個人結果、瞬き検出結果、主要版、Set 4〜6は変更しない。

追加figureと対応CSVには `ExcludePair133-233_Sets1-3` を付ける。

**理由：** 片条件だけを除外して被験者内対応を崩さず、ID233前半3セットの信号品質上の懸念が集団結果へ与える影響を確認するため。

## 6. 実行と再現性

被験者対応は、次の4列を持つ非公開manifestから読み込む。

```text
first_session_id, second_session_id, drops_session_id, product
```

本番実行前に `--production-batch --preflight-only` を使い、40被験者ペア・80セッション、製品群各20名、ID重複、対象外ID、既知の欠測セット、HDF5構造、主解析列の有限性を出力なしで検証する。合格後、同じmanifestとスクリプトで全個人結果、Grand-average、セット別定量化を一括作成する。

既存の個人結果と検出結果を保持し、集団出力だけを再作成する場合は `--production-batch --group-outputs-only` を使用する。このモードも同じ40ペアmanifestを要求し、既存の被験者別CSVから主要版と追加版を再現する。

Grand-average図だけを再作成し、セット別定量化を変更しない場合は `--grand-average-only` を併用する。

結果はOneDriveへ保存し、被験者ペア別の検出数、閾値、欠測、目視QC、条件間瞬き数バランスをNotionへ記録する。

## 7. 解析結果の位置づけ

- 主要結果：全使用可能データを用いた製品群別Grand-averageとセット別定量化
- 追加結果：Vロートプレミアム群のPair 133–233 Set 1〜3を両条件から外した集団結果
- Quality Check：検出信号とピーク位置の目視整合性、および両条件の共通セットにおける総検出数比
- 推測統計：現段階では実施しない

目視QCは真の瞬きラベルに対する感度・適合率の検証ではなく、自動検出と波形の定性的整合性を確認するものである。
