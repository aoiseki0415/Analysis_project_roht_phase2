# 運用ルール

## 1. 目的と適用範囲

この文書は、ロート製薬フェーズ2の本解析における、GitHub、ローカルデータ、OneDrive、Google Drive、Notionの使用目的と制限を定めます。

作業開始時には、必ず先にルートの `README.md` を確認します。この文書はREADMEの詳細規則です。

## 2. GitHubとルートリポジトリ

### 目的

- 解析スクリプトと運用文書を管理する
- 解析手順を再現可能にする
- 変更履歴を個人リポジトリへ残す

### 許可された対象

- ローカルルート：`/Users/aoiseki/GitHub/Analysis_project_roht_phase2`
- GitHubリモート：`https://github.com/aoiseki0415/Analysis_project_roht_phase2.git`

これ以外のリポジトリ、リモート、Gitアカウントは操作しません。特に、SandBox全体側のGitは絶対に操作しません。

### フォルダ運用

- 現行スクリプトは `解析プログラム/` に置きます。
- 完全に不要になったスクリプトは `解析プログラム（過去版いらなくなったやつ）/` へ移します。
- `参考資料（プログラミング関連）/` は原則として参照専用です。

参考資料のうち、ガボール課題関連資料からは、課題内容、実装、イベント、行動ログ、EEGとの時刻同期、取得データの構造を確認します。過去のMATLAB解析からは、脳波の前処理、行動データ解析、脳波解析、ERP、時間周波数解析などの細かな処理手順と手法を確認します。本解析の設計時には、これらを重要な技術的参考資料として扱います。

### Git操作

Git操作のたびに、少なくとも次を内部確認します。

1. `git rev-parse --show-toplevel` が許可されたローカルルートと一致する
2. `git remote get-url origin` が許可されたリモートと完全一致する
3. ステージ対象が今回変更した明示的なファイルだけである
4. 生データ、個人情報、被験者ID、解析結果が含まれていない
5. `git diff --cached --check` が成功する

コードや運用文書を変更した場合は、必要な検証を行い、commitとpushまで自動で完了します。許可されたリポジトリ内で作業を完了するために必要な通常のGit操作について、種類を問わず利用者へ都度承認を求めません。これには、状態・差分・履歴・リモートの確認、ステージ、commit、fetch、pull、push、リモート反映確認などを含みます。push成功とリモート反映を確認してから内容を共有します。

この承認省略は、許可された個人リポジトリ内の通常運用に限ります。他リポジトリ、SandBox全体側のGit、未確認のリモートへの操作、履歴破壊を目的とする操作へ範囲を広げるものではありません。実行環境が技術的に承認入力を強制する場合を除き、通常のGit操作に関する確認質問を利用者へ送りません。

許可範囲からの逸脱、想定外のリモート、別リポジトリでの実行、意図しないファイルの混入を検出した場合は、操作を止め、早急に利用者へ報告します。

## 3. 生データ

### 対象

`/Users/aoiseki/Desktop/SandBox_ロート案件（データ）`

ファイルシステム上ではUnicode表現が異なって見える場合がありますが、同名の指定フォルダだけを対象とします。

### 目的

- 解析対象となる生データの読み込み

### 制限

- 読み取り専用とし、編集・上書き・削除・改名・移動を行いません。
- GitHub、Google Drive、Notion、その他の外部サービスへアップロードしません。
- リポジトリやOneDriveへ生データのコピーを作りません。
- 解析結果の出力先として使用しません。
- 対象フォルダ外のデスクトップ領域は使用しません。

## 4. OneDriveの解析結果

### 対象

`/Users/aoiseki/Library/CloudStorage/OneDrive-個人用/デスクトップ/SandBoxプロジェクト/ロート製薬フェーズ2 2026.5/実験本番_本解析`

### 目的

- figure、表、集計結果、処理済みの解析結果、実行ログなどの保存

### 運用

- 解析スクリプトの出力先には、必ずこのフォルダまたはその配下を明示します。
- 他の場所へ解析結果を保存しません。
- 上書きを避ける必要がある成果物には、解析名、日付、版などを付けます。
- OneDriveの他のフォルダは使用しません。
- 生データの原本は保存しません。

このフォルダは、利用者の運用許可上は自由に作成・編集できます。実行環境のサンドボックスが書き込みを拒否した場合は、別の場所へ代替保存せず、未完了の状態と制約を報告します。

## 5. Google Drive

### 対象

`マイドライブ / SandBox関連 / ロート製薬PJ フェーズ2 2026.5~ / 実験本解析_Codex共有用`

### 目的

- スプレッドシートから被験者ID、実験条件、解析に必要な対応関係を確認する
- MTGドキュメントから解析方針と背景を確認する
- 開発要件や実験資料を参照する

### 制限

- 指定フォルダ外を使用しません。
- 原則として閲覧のみとし、編集・移動・削除・共有設定変更・複製を行いません。
- 閲覧時の通常承認は求めません。
- 共有フォルダ内のスプレッドシートは匿名化済みであり、解析に必要な範囲を自由に確認できます。
- 被験者IDは、条件対応や解析処理に必要な範囲で内部利用できます。Git、README、回答文へは記載しません。個人情報を含まない匿名IDの対応表は、解析に不可欠で利用者から記録を指示された場合に限り、許可されたNotion配下で管理できます。
- Google Driveを生データや解析結果の保存先にしません。

## 6. Notion

### 対象

`研究ワークスペース / SandBox案件_ロート2`

### 目的

- 解析ストーリーと解析方針の整理
- 日々の解析記録
- 結果に基づく結論と解釈の可視化
- ツール利用上の留意点の管理

### 運用と制限

- 指定ページとその配下だけを閲覧・編集します。
- 指定範囲内の通常編集について承認を求めません。
- 他のNotionワークスペースやページは絶対に操作しません。
- 生データと個人情報は記載しません。匿名IDは、条件・セッション対応、欠測、品質上の例外など解析に不可欠な情報に限り記載し、氏名等と結び付けません。
- 成果物の本体はOneDriveへ保存し、Notionには目的、方法、要約、解釈、保存場所を記録します。
- 解析方針の相談内容が確定したら、「解析ストーリー」など適切なページへ反映します。
- 観察結果、解釈、仮説、未確定事項を区別します。
- 解析スクリプトの作成・実行、対象データの抽出、集計の前に、`解析ストーリー` 配下の全ページを毎回確認します。
- `被験者・セッションID対応表` と `解析の際に注意すべき点` に記載された解析使用可否、除外、分割記録の統合方法を、解析対象選定の正本とします。
- Notionの内容がGit文書や過去の会話と異なる場合は、最新のNotionを確認し、矛盾を解消してから解析します。

## 7. 日々の解析記録

解析作業を実施した日は、Notionの `解析の記録` に次を記録します。

- 実施日
- 解析の目的
- 使用したデータの範囲
- 実施した前処理・解析手法
- 使用したスクリプトと版
- 関連するGit commit番号（リポジトリ変更がある場合。pushとリモート反映確認後に記録）
- 得られた結果
- 結果の解釈
- OneDrive上の出力先
- 問題、データ品質上の注意、未確定事項
- 次に行うこと

個人情報や生データそのものは記録しません。

同日の作業で複数のcommitが生じた場合は、解析記録から変更履歴を追跡できるよう、該当するcommit番号と変更内容を対応付けて記録します。リポジトリ変更がない作業では、commit番号を無理に付与しません。

## 8. 自律的な文書更新

プロジェクトの作業中に、恒常的な運用ルール、解析方針、重要な前提、解析結果、次の作業が新たに確定した場合は、利用者から改めて指示されるのを待たず、同じ作業の中で次を更新します。

- ルートREADMEと関連するGitHub文書
- 必要に応じた個別解析の仕様書
- Notionの「解析ストーリー」「解析の記録」「留意点」のうち該当するページ

リポジトリ内の文書またはスクリプトを変更した場合は、検証、commit、push、リモート確認まで完了してから利用者へ共有します。通常の更新では承認を求めません。

## 9. 承認と例外

許可済みの対象における通常の閲覧、編集、Notion更新、および作業に必要なすべての通常Git操作について、利用者へ毎回の承認を求めません。

ただし、次の場合は処理を止め、状態を報告します。

- 許可対象を一意に特定できない
- Gitリポジトリまたはリモートが一致しない
- 対象外のフォルダ、Google Drive、Notion領域を操作する必要がある
- 生データまたは個人情報が外部へ保存される可能性がある
- システム上の権限制約により、指定先へ書き込めない
- 削除、大量上書き、共有設定変更など、通常運用を越える不可逆性の高い操作が必要になる

実行環境が強制的に承認を要求する場合は、利用者が定めた通常運用上の承認省略とは別の技術的制約として扱います。
