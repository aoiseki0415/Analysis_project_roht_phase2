# 運用ルール

## 1. 目的と適用範囲

この文書は、ロート製薬フェーズ2の本解析における、GitHub、ローカルデータ、OneDrive、Google Drive、Notionの使用目的と制限を定めます。

作業開始時には、必ず先にルートの `README.md` を確認します。この文書はREADMEの詳細規則です。

## 2. GitHubとルートリポジトリ

### 目的

- 解析スクリプトと運用文書を管理する
- 解析手順を再現可能にする
- 変更履歴を個人リポジトリへ残す

### 許可された対象

- ローカルルート：`/Users/aoiseki/GitHub/Analysis_project_roht_phase2`
- GitHubリモート：`https://github.com/aoiseki0415/Analysis_project_roht_phase2.git`

これ以外のリポジトリ、リモート、Gitアカウントは操作しません。特に、SandBox全体側のGitは絶対に操作しません。

### フォルダ運用

- 現行の解析スクリプトは、`解析プログラム/` 配下の該当する5フェーズのフォルダに置きます。
- フェーズフォルダは `Phase1_脳波前処理`、`Phase2_行動データ解析`、`Phase3_瞬き解析`、`Phase4_脳波解析`、`Phase5_相関・その他` とします。
- スクリプト名は `Phase<フェーズ番号>_No<解析番号>_<内容>.py` とします。同じNoを、OneDriveの成果物とローカルの中間データへ対応付けます。
- 完全に不要になったスクリプトは `解析プログラム（過去版いらなくなったやつ）/` へ移します。
- `参考資料（プログラミング関連）/` は原則として参照専用です。

参考資料のうち、ガボール課題関連資料からは、課題内容、実装、イベント、行動ログ、EEGとの時刻同期、取得データの構造を確認します。過去のMATLAB解析からは、脳波の前処理、行動データ解析、脳波解析、ERP、時間周波数解析などの細かな処理手順と手法を確認します。本解析の設計時には、これらを重要な技術的参考資料として扱います。

### Git操作

Git操作のたびに、少なくとも次を内部確認します。

1. `git rev-parse --show-toplevel` が許可されたローカルルートと一致する
2. `git remote get-url origin` が許可されたリモートと完全一致する
3. ステージ対象が今回変更した明示的なファイルだけである
4. 生データ、個人情報、解析結果が含まれていない。匿名IDは、解析に不可欠な例外処理を `docs/解析上の注意事項.md` に記録する場合に限る
5. `git diff --cached --check` が成功する

コードや運用文書を変更した場合は、必要な検証を行い、commitとpushまで自動で完了します。許可されたリポジトリ内で作業を完了するために必要な通常のGit操作について、種類を問わず利用者へ都度承認を求めません。これには、状態・差分・履歴・リモートの確認、ステージ、commit、fetch、pull、push、リモート反映確認などを含みます。push成功とリモート反映を確認してから内容を共有します。

この承認省略は、許可された個人リポジトリ内の通常運用に限ります。他リポジトリ、SandBox全体側のGit、未確認のリモートへの操作、履歴破壊を目的とする操作へ範囲を広げるものではありません。実行環境が技術的に承認入力を強制する場合を除き、通常のGit操作に関する確認質問を利用者へ送りません。

許可範囲からの逸脱、想定外のリモート、別リポジトリでの実行、意図しないファイルの混入を検出した場合は、操作を止め、早急に利用者へ報告します。

## 6. Notion

### 対象

`研究ワークスペース / SandBox案件_ロート2`

### 目的

- 解析ストーリーと解析方針の整理
- 日々の解析記録
- 結果に基づく結論と解釈の可視化
- ツール利用上の留意点の管理

### 運用と制限

- 指定ページとその配下だけを閲覧・編集します。
- 指定範囲内の通常編集について承認を求めません。
- 他のNotionワークスペースやページは絶対に操作しません。
- 生データと個人情報は記載しません。匿名IDは、条件・セッション対応、欠測、品質上の例外など解析に不可欠な情報に限り記載し、氏名等と結び付けません。
- 成果物の本体はOneDriveへ保存し、Notionには目的、方法、要約、解釈、保存場所を記録します。
- 解析方針の相談内容が確定したら、「解析ストーリー」など適切なページへ反映します。
- 5フェーズそれぞれの方針、実施内容、結果、解釈、未確定事項は、解析ストーリー配下の対応するフェーズページへ記録します。
- すべてのフェーズで、Cキューブ群とVロートプレミアム群を分け、それぞれで目薬あり条件とコントロールを比較します。
- 観察結果、解釈、仮説、未確定事項を区別します。
- 解析スクリプトの作成・実行、対象データの抽出、集計の前に、`解析ストーリー` 配下の全ページを毎回確認します。
- 同じタイミングで、GitHubの `docs/解析上の注意事項.md` を毎回確認します。
- `被験者・セッションID対応表` と `解析の際に注意すべき点` に記載された解析使用可否、除外、分割記録の統合方法を、解析対象選定の正本とします。
- Phase 1実行時は、Phase 1配下の「ICA処理結果（ID別）」へ、ICA学習除外チャンネル、区間除外の要約、ICA収束、除去IC番号と確率、「瞬き成分除去の精度」、「空間的バランス」を簡潔に記録します。区間ごとの時刻・理由・影響チャンネル数、詳細figure、品質管理表はOneDriveへ保存し、Notionへ長文で重複転記しません。
- 瞬き成分除去精度は、データ保存後かつ前処理完了確定前に、`QC01_BlinkCheck`（Fp1・Fp2のみ）を開いてから最大3分で0～100点で概算評価します。約150～200秒幅の表示窓を重複なく送り、全時間帯を少なくとも1回高速走査します。BeforeのFp1・Fp2の同時刻に現れる短時間の同期した尖りまたは丘状波形を瞬き候補とし、Afterで両方から明瞭に消失・抑制したものを正常除去、片側のみまたは部分的な抑制を不完全除去、残存・悪化を未除去とします。精度は5～10点刻みの目視概算とし、片側だけの不規則波形やセット境界付近の巨大変動は瞬きと断定しません。`QC05_ICAExclusionReview`は精度採点に使わず、評価後は該当HTMLタブを必ず閉じます。
- 同じ完了前QCで、除去ICごとのtopomap PNGを確認し、Fp1・Fp2の空間的バランスを「良好／一部偏り／片側偏重」の3段階で記録します。各ICが左右バランスする、または除去IC全体でFp1寄りとFp2寄りが補完していれば良好、一部に偏りはあるが両側が代表されれば一部偏り、除去IC全体が一方に偏れば片側偏重とします。この評価はQCだけに使い、IC除去基準には追加しません。
- Phase 1の各IDを処理した後は、「前処理完了確認（ID別）」で、読込、入力異常、フィルタ、トレンド除去、ICA学習除外チャンネル記録、区間除外、ICA、成分除去、セット分割、保存の10工程をチェックボックスで記録します。ICAの反復回数、除外区間、ICLabel確率、除去IC等の詳細は「ICA処理結果（ID別）」へ分離します。
- `被験者・セッションID対応表` では、各ペアの条件順を「目薬使用回」（1回目／2回目）で管理します。「目薬ID」「対照ID」列は使用しません。
- Notionデータベースは、利用者が調整した現在の列構成を正とします。利用者が削除したプロパティを、過去のスキーマや会話に基づいて自動復元しません。現在の「メモ一覧」は「メモ」「対象」「日付」の3列で運用します。
- Notionの内容がGit文書や過去の会話と異なる場合は、最新のNotionを確認し、矛盾を解消してから解析します。

## 7. 解析実行記録

通常の解析実行では、日次作業ログや被験者別結果表をNotionへ作成しません。次の情報は、各Phaseで指定されたOneDrive成果物ツリーの `Sub/logs/` と補助CSVへ記録します。

- 実施日
- 解析の目的
- 使用したデータの範囲
- 実施した前処理・解析手法
- 使用したスクリプトと版
- 関連するGit commit番号（リポジトリ変更がある場合）
- 得られた結果
- 結果の解釈
- OneDrive上の出力先
- 問題、データ品質上の注意、未確定事項
- 次に行うこと

個人情報や生データそのものは記録しません。コードと文書の変更履歴は、push・リモート一致を確認したGit履歴を正本とします。

同日の作業で複数のcommitが生じた場合は、実行ログから変更履歴を追跡できるよう、該当するcommit番号と変更内容を対応付けます。リポジトリ変更がない作業では、commit番号を無理に付与しません。

Notionは、解析方針、確定仕様、恒常的な注意事項の管理に使用します。個別Phaseで利用者が明示的に結果表を指定した場合だけ、その指定範囲で結果を記録します。過去に作成済みのPhase 1〜3結果記録は履歴として維持し、本規則を理由に削除・改変しません。

## 8. 自律的な文書更新

プロジェクトの作業中に、恒常的な運用ルール、解析方針、重要な前提、解析結果、次の作業が新たに確定した場合は、利用者から改めて指示されるのを待たず、同じ作業の中で次を更新します。

- ルートREADMEと関連するGitHub文書
- 必要に応じた個別解析の仕様書
- Notionの「解析ストーリー」「留意点」のうち、方針・確定仕様・恒常的注意事項に該当するページ

リポジトリ内の文書またはスクリプトを変更した場合は、検証、commit、push、リモート確認まで完了してから利用者へ共有します。通常の更新では承認を求めません。

## 9. 承認と例外

許可済みの対象における通常の閲覧、編集、Notion更新、および作業に必要なすべての通常Git操作について、利用者へ毎回の承認を求めません。

Phase 1の不良チャンネル候補は、公式由来の指標を基本としつつ、局所的な一時ノイズや単一指標で過剰除外しない保守的な自動除外基準を使います。該当チャンネルがある場合は、OneDriveへフィルタ・トレンド除去後の0 µV中心波形figureと根拠を保存し、利用者承認なしでICA学習・ICA適用対象からだけ除外して処理を継続します。最終32チャンネルEEGでは当該チャンネルを削除・NaN化せず、フィルタ・トレンド除去済み信号を保持します。不良区間のICA学習用データからの自動除外と、ICLabelによるEye成分除去にも事前承認を求めません。各除外結果とEye成分除去は、事後確認用成果物と記録を残します。

ただし、次の場合は処理を止め、状態を報告します。

- 許可対象を一意に特定できない
- Gitリポジトリまたはリモートが一致しない
- 対象外のフォルダ、Google Drive、Notion領域を操作する必要がある
- 生データまたは個人情報が外部へ保存される可能性がある
- システム上の権限制約により、指定先へ書き込めない
- 削除、大量上書き、共有設定変更など、通常運用を越える不可逆性の高い操作が必要になる

実行環境が強制的に承認を要求する場合は、利用者が定めた通常運用上の承認省略とは別の技術的制約として扱います。

## 10. 解析スクリプトの確定と再実行

- 本番一括処理の前にパイロットIDでスクリプト、パラメータ、完了条件を確定します。
- 確定後は同一のGit版、同一のパラメータ、同一の判定基準を全IDへ適用し、IDごとに都合よく変更しません。
- 正常完了したIDを理由なく再処理しません。再処理は実装不具合、出力欠損、または利用者と合意した仕様変更がある場合だけ行い、理由を解析記録へ残します。
- Phase 2以降の `Individual/` と `GrandAverage/` にはPNGだけを保存し、被験者別figureは製品群の `Individual/` 直下へ並べます。定量化フォルダは例外とし、通常解析のセット別PNG・全Set統合PNG・統計CSVを直下へ置きます。追加解析は内容が分かる下位フォルダを作り、同じ3種の成果物を保存します。統計CSVは未補正・Bonferroni・Holm・Benjamini–Hochberg FDRのp値を含みます。その他の補助成果物とログは各No直下の `Sub/` へ分離します。
- Phase 3 No1は `No1_BlinkRate/` 直下で製品群を先に分け、製品群内を `Individual/`、`GrandAverage/`、`SetQuantification/`、`QualityCheck/` に分けます。インタラクティブHTMLと同じResetスケールの横長PNGは `QualityCheck/BlinkDetection/` に一緒に保存し、prominence分布PNGは `QualityCheck/ProminenceDistribution/` に保存します。検出確認の青線は、Phase 1でICLabelのEye成分として除去したICのチャンネル別寄与（ICA前EEG−除去後EEGと同値）をセンサー空間へ戻し、使用可能なFp1・Fp2を時点ごとに平均した後、Phase 3で1–10 Hzフィルタを適用した `Eye Blink Component Signal` とします。通常はFp1・Fp2平均ですが、一方がICA学習除外なら残るFp信号を主解析列とし、補助列だけをNaNに保ちます。ID124・209はFp2補助列が全SetでNaNですが、主解析列は有限なので他IDと同じ処理を行います。凡例は `Eye Blink Component Signal`、縦軸は `Amplitude (µV)` とします。HTML Resetと横長PNGの縦軸半幅は全使用Setの絶対振幅99.5パーセンタイル×1.60とし、Set名が波形に埋もれない余白を確保します。検出確認成果物は `Pair<1回目>-<2回目>_01_ID<1回目>`、`..._02_ID<2回目>` の接頭辞を用い、ファイル名順が101、201、102、202のように被験者ペア内の実施順になるよう固定します。prominence閾値の係数12は文献値ではなく、探索比較と係数10の初回全対象結果で確認した過剰検出を踏まえた全ID共通値です。IDごとの上位一定割合と抽出総数を似通わせうるパーセンタイル方式は使用しません。本番一括実行前は全40ペア・80セッション、製品群各20名、重複、対象外ID、既知の欠測Set、HDF5構造、主解析列の有限性を出力なしで全件事前検証します。
- Phase 3 No1の主要集団結果は全使用可能データで保持します。Vロートプレミアム群では、ID233 ControlのSet 1〜3で瞬き成分が十分に抽出されていないという事後確認への追加解析として、被験者内対応を保つためID133–233の両条件のSet 1〜3を群集計だけから外したGrand-average・セット別定量化も作成します。追加成果物には `ExcludePair133-233_Sets1-3` を付け、個人結果・検出結果・主要集団結果を変更しません。
- Phase 3 No1のGrand-averageには、標準の0始まり自動スケール版を保持したまま、Cキューブ主要版、Vロートプレミアム主要版、VロートプレミアムのID133–233 Set 1〜3除外版について、共通の10〜30 blinks/min・5 blinks/min刻み・薄いグレーの横グリッドを用いる拡大表示版を追加します。ファイル名には `FocusedYAxis_10to30BlinksPerMin` を付けます。この追加生成では個人図、検出QC、prominence分布、セット別定量化を再生成しません。
- Phase 3 No1のNotion親ページには確定事項の要約だけを置き、詳細手法は子ページへ分離します。結果は1行1被験者ペアの統合表とし、各行ページ内へ2セッションのQuality Checkとセッション・Set別結果表をまとめます。各セッションのHTMLは最大3分で、x軸を個々のスパイクが見える幅まで拡大し、連続する表示窓で全使用時間を走査します。Reset全景だけで評価せず、確認後はHTMLを閉じます。被験者ペアの両条件で使用可能な共通Setの総検出数を比較し、大きい方÷小さい方が2倍以上または片方0なら `条件間瞬き数バランス=要確認`、2倍未満なら `概ね同程度` と記録します。このQCだけを理由に除外やID別閾値変更を行いません。
- Phase 4のNotion親ページにはNo1、No1_add、No1_sub、No2、No3の概要だけを独立見出しで置き、計算、figure、保存、欠測、統計の詳細は各解析の子ページへ分離します。解析対象chの文献調査はNo1詳細ページの子ページとして管理します。
- Phase 4 No1は、全32chの4–7 Hz平均PSD時間変化をセッションIDごとのHDF5へ一度だけ保存し、個人figure、Grand-average、定量化・統計、topographyは保存済みPSDを再利用します。figureの体裁変更だけでPSDを再計算しません。
- Phase 4 No1のPSDは1秒Hann窓を1秒ずつ移動して計算します。ローカルcacheは未平滑PSDを正本とし、平滑値で上書きしません。
- Phase 4 No1ではPhase 1区間maskの適用後、各セッションID・chについて利用可能な全Setの有限かつ正の未平滑4–7 Hz平均PSDをプールし、`log10(PSD)`の平均＋3標準偏差（`ddof=1`）を超える上側値だけを、そのch・時間窓でNaNにします。Set別、対応セッション混合、条件横断、下側除外は行いません。元PSDを上書きせず、log閾値、線形閾値、mask、Set・ch別の除外数・率をcacheへ保存します。
- Phase 4 No1の個人時間変化とGrand-averageは、各Set内だけで60秒中心化単純移動平均を適用します。NaNは無視し、窓内に1点以上の有限値があれば平均を算出し、窓全体がNaNの場合だけNaNとします。平滑化後に各Setをprogress 100点へ対応付け、被験者間平均します。Grand-averageのy軸は最大mean＋SEMを約75%の高さに置く標準規則を使います。定量化とtopographyは未平滑PSDを使用します。
- Phase 4 No1の `Individual/` 直下に3SD mask適用後・60秒平滑化後の主figure、`Individual/Unsmoothed/BeforeThresholdExclusion/` と `AfterThresholdExclusion/` に未平滑の閾値除外前後figureを保存します。固定y軸版と探索用平滑化比較は本番成果物に残しません。
- Phase 4 No1 topographyは未平滑PSDのSet時間平均から `Eye Drop − Control` を求めます。同一図の6 Set・32chの最大絶対差を `M` とし、`M / 0.85` 以上の切りのよい値 `V` を上限とする `−V〜+V` 左右対称スケールを用います。
- Phase 4 No1の個人時間変化では、既知の欠測Setについて欠測セッション側だけを非表示とします。Grand-average、定量化、条件差topographyでは被験者内対応を保つため、対応セッション側も同じSetから除外し、欠測を補間しません。
- Phase 4 No1の計算関数・全引数、Set端padding、progress換算、PSD cache構造、未適用処理、実行モード、全figure定数、統計位置、topography設定、命名、検証条件は `docs/Phase4_脳波解析仕様.md` を唯一の実装正本とします。実装者の裁量でPhase 2・3を再解釈して数値を置き換えません。
- Phase 4 No1_addはNo1本体から独立させ、将来の `Phase4_No1_add_FzTimeFrequencyMap.py`、ローカル `No1_add_FzTimeFrequencyMap/`、OneDrive `No1_add_FzTimeFrequencyMap/` を使用します。Fz 1–30 Hzの線形PSDを保存し、No1のシータmaskを流用しません。
- No1_addではPhase 1区間mask適用後、各Fz時間窓の1–30 Hz平均PSDからセッションID別・全Set一括の `log10` 平均＋3標準偏差を求め、上側外れ時間窓の全周波数binをNaNにします。その後、周波数bin別のSet内60秒中心化単純移動平均、Set別100 progress点化、被験者間平均を行います。製品群別にEye Drop、Control、`ΔPSD = Eye Drop − Control` の3段TFMだけを作り、個人TFMは作成しません。完全仕様は `docs/Phase4_No1_add_FzTimeFrequencyMap仕様.md` を正本とします。
- Phase 4 No1_subはNo1本体と独立した `Phase4_No1_sub_FmThetaChange.py` を使い、ローカルのNo1 PSD cacheから開始します。セッションID・ch別のSet 1有限値平均をbaselineとし、平滑化前に `(PSD / baseline - 1) × 100` へ変換します。Fz時間変化は変換後にSet内60秒平滑化、定量化とtopographyは未平滑変化率を使用します。全Set統合定量値はSet 1を含むSet 1–6の全有限時間窓を直接平均します。Grand-averageは平均線の最大絶対値をy軸の約70%、定量化は0より上：下を約2：1とし、Set名を統計表示より十分上へ離して置きます。派生cacheはローカルへ保存せず、OneDrive `No1_sub_FmThetaChange/` だけへ出力します。ID109のSet 1欠測によりペア109–209はNo1_sub全体から除外します。完全仕様は `docs/Phase4_No1_sub_FmThetaChange仕様.md` を正本とします。
- ICA内部の反復回数は1回のICA学習内の最適化回数であり、IDの再処理回数ではありません。収束している限り、反復回数の違いだけを再処理理由にしません。
- 不良チャンネル候補だけを理由に利用者判断待ちで停止しません。保守的基準に該当したチャンネルはICA用データからだけ自動除外し、確認待ちによる完了済み工程のやり直しを発生させません。
- Phase 1の全IDへ、同じパイプライン仕様版、固定乱数シード、フィルタ・ICAパラメータ、QC figureスタイル版、色、サイズ、解像度、ファイル命名を適用します。ID固有の例外は、事前に合意して固定した分割セット対応と、自動判定されたICA学習除外チャンネルだけです。

- 毎回の実行直前に、ルートREADME、本文書、`docs/解析上の注意事項.md`、`docs/Phase1_脳波前処理仕様.md`、`解析プログラム/Phase1_脳波前処理/README.md`、Notionの解析ストーリー配下を確認します。前回確認済みであることを理由に省略しません。
